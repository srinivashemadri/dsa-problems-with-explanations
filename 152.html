LeetCode 152 — Maximum Product Subarray

Step 1 — Problem Statement

Input: An integer array nums containing at least one number. You must find a contiguous subarray whose product is the largest among all possible contiguous subarrays.

Output: The maximum product value of any contiguous subarray.

Key Constraints: The subarray must be contiguous, so you cannot pick elements independently. The array may contain positive numbers, negative numbers, and zero. The sign of the product matters just as much as the magnitude, because multiplying by a negative number can completely flip the ordering of values.

Edge Cases: a single element array, all positive values, all negative values, zeros splitting the array into independent segments, an odd number of negative values, and cases where the best answer is not the whole array but a middle segment.

Step 2 — Problem Understanding & Approach Overview

This problem is really asking for the best product over every contiguous segment, not just the segment with the largest sum-like behavior. The core challenge is that multiplication with negative numbers is non-monotonic: a very small negative product can become the largest positive product after multiplying by another negative number.

Category: Dynamic Programming / Prefix-style state tracking.

Mental model: At each index, do not only ask “what is the best product ending here?” Also ask “what is the worst product ending here?” because the worst one may become the best one after the next negative number.

Subtle trap: Many candidates track only the maximum product so far. That fails on inputs like -2 3 -4, where the answer is 24. The negative value that looked bad at one step becomes the key to the final answer.

Step 3 — Brute Force Solution

The naive idea is to try every contiguous subarray, compute its product, and keep the maximum. 

for i from 0 to n - 1:
    product = 1
    for j from i to n - 1:
        product = product * nums[j]
        answer = max(answer, product)
return answer

Time Complexity: O(n²). There are two nested loops, and each pair (i, j) defines one subarray.

Space Complexity: O(1). Only a few variables are used.

Performance bottleneck: The number of subarrays is quadratic, and recomputing products repeatedly is expensive.

Step 4 — Intuition Building

Test Case 1

Input: 2 3 -2 4
    Start with 2
    Best ending here = 2
    Worst ending here = 2

At 3:
    Extend previous best: 2 * 3 = 6
    Start fresh: 3
Action: choose max ending product = 6, min ending product = 3
Result so far: 6

At -2:
    Negative flips roles:
    Previous best * -2 = 6 * -2 = -12
    Previous worst * -2 = 3 * -2 = -6
Action: best ending here = max(-2, -12, -6) = -2
        worst ending here = min(-2, -12, -6) = -12
Result so far: 6

At 4:
    Best ending here = max(4, -2 * 4 = -8, -12 * 4 = -48) = 4
    Worst ending here = min(4, -8, -48) = -48
Action: global answer stays 6
Result: 6

Test Case 2

Input: -2 0 -1
    Start with -2
    Best ending here = -2
    Worst ending here = -2

At 0:
    Zero breaks every product chain
Action: best ending here = max(0, -2 * 0, -2 * 0) = 0
        worst ending here = 0
Result so far: 0

At -1:
    Starting fresh from -1 is better than extending zero
Action: best ending here = max(-1, 0 * -1, 0 * -1) = 0
        worst ending here = -1
Result: 0

Test Case 3 (Edge Case)

Input: -2 3 -4
    At -2:
        best = -2
        worst = -2

    At 3:
        best = max(3, -2 * 3 = -6, -2 * 3 = -6) = 3
        worst = min(3, -6, -6) = -6

    At -4:
        negative flips the meaning of best and worst
        best = max(-4, 3 * -4 = -12, -6 * -4 = 24) = 24
        worst = min(-4, -12, 24) = -12

Action: keep both best and worst ending at each position
Result: 24

The pattern is clear: the product state must carry both extremes because a negative number can swap them. A zero also acts like a reset point, because any product passing through it becomes zero.

A future problem should trigger the same approach when the operation can flip order based on sign, parity, or reversal of comparison — especially when a “bad” intermediate state can later become the best answer.

Step 5 — Optimized Solution

There is only one meaningful optimized solution here: dynamic tracking of the maximum and minimum product ending at each position.

Idea: For every index, maintain:

maxEnd = maximum product of a subarray ending at the current index
minEnd = minimum product of a subarray ending at the current index

When the current number is negative, the two values are swapped in effect, because multiplying by a negative reverses which one is useful.

Clean Pseudocode:

ans = nums[0]
maxEnd = nums[0]
minEnd = nums[0]

for i from 1 to n - 1:
    x = nums[i]
    if x < 0:
        swap(maxEnd, minEnd)

    maxEnd = max(x, maxEnd * x)
    minEnd = min(x, minEnd * x)

    ans = max(ans, maxEnd)

return ans

Full Working C++17 Code:

int maxProduct(vector<int>& nums) {
    long long maxEnd = nums[0];
    long long minEnd = nums[0];
    long long ans = nums[0];

    for (int i = 1; i < (int)nums.size(); ++i) {
        long long x = nums[i];

        if (x < 0) {
            swap(maxEnd, minEnd);
        }

        maxEnd = max(x, maxEnd * x);
        minEnd = min(x, minEnd * x);

        ans = max(ans, maxEnd);
    }

    return (int)ans;
}

Dry Run on a Meaningful Test Case:

Input: -2 3 -4

Initial:
    maxEnd = -2
    minEnd = -2
    ans = -2

Step 1: x = 3
    x is positive, no swap
    maxEnd = max(3, -2 * 3 = -6) = 3
    minEnd = min(3, -2 * 3 = -6) = -6
    ans = max(-2, 3) = 3

Step 2: x = -4
    x is negative, swap maxEnd and minEnd
    maxEnd = -6
    minEnd = 3

    maxEnd = max(-4, -6 * -4 = 24) = 24
    minEnd = min(-4, 3 * -4 = -12) = -12
    ans = max(3, 24) = 24

Final Result: 24

How the zero edge case is handled: When x = 0, both maxEnd and minEnd become 0, which naturally resets the chain. The next non-zero value can start a fresh subarray.

Time Complexity: O(n). The array is scanned once, and each step does constant work.

Space Complexity: O(1). Only a fixed number of variables are used.

Algorithm Name: Dynamic Programming with max/min tracking.
