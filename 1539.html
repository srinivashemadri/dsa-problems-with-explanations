LeetCode 1539 — Kth Missing Positive Number
Step 1 — Problem Statement

Input: A strictly increasing sorted array of positive integers arr, and a positive integer k. The array contains some positive numbers, but not all of them. The missing positive numbers are the positive integers that do not appear in the array.

Output: Return the kth missing positive number.

Key Constraints: The array is sorted in strictly increasing order, so every next element is larger than the previous one. That single fact is the reason the problem can be solved efficiently. Also, the numbers are positive, which means the missing sequence starts from 1 and grows upward.

Edge Cases: The kth missing number may be before the first array element, inside a gap between two array elements, or after the last array element. There may be no gap at all in the array, the array may have only one element, and k may be small enough that the answer is very close to the beginning.

Step 2 — Problem Understanding & Approach Overview

What this problem is really asking is: among all positive integers, find the kth one that is absent from a sorted list of present numbers. The story is not important. The core challenge is that the missing numbers are not explicitly stored, so we must infer them from gaps.

This is a sorted array + monotonic count problem. The instinctive mental model is to stop thinking about every number one by one and instead think about how many numbers are missing up to a certain index.

The subtle trap most candidates fall into is counting missing numbers by brute force from 1 upward without using the sorted structure. Another common mistake is getting the indexing wrong when computing how many numbers are missing before arr[i].

Step 3 — Brute Force Solution

The most naive way is to check positive integers one by one, and for each candidate, scan the array to see whether it exists. Every time a candidate does not exist in the array, it is a missing positive number. Keep counting until you reach the kth one.

Pseudocode:

candidate = 1
while k > 0:
    if candidate is not present in arr:
        k = k - 1
    candidate = candidate + 1

return candidate - 1

Time Complexity: O(M × n), where M is the value range we need to scan until the kth missing number appears. For every candidate, we may scan the whole array to check existence. This becomes slow because we repeatedly inspect the same array for every positive integer.

Space Complexity: O(1) if we do a direct linear scan for membership.

Performance Bottleneck: The bottleneck is not the counting itself; it is the repeated checking of each integer one by one. That ignores the sorted order and wastes work on numbers we could have skipped in bulk.

Step 4 — Intuition Building

The key discovery is that the array already tells us where the missing numbers are: in the gaps. Instead of checking every positive integer, we inspect how many numbers are absent before each array element.

Test Case 1

Input: 2 3 4 7 11, k = 5

Current state: the gaps are 1, then 5 6, then 8 9 10, and so on.

Action: count missing numbers in order — 1, 5, 6, 8, 9, ...

Result: the 5th missing positive number is 9.

Observation: brute force would still test 1, 2, 3, 4, 5, 6, 7, 8, 9 individually. The pattern is clearly in the gaps, so the work should be done per gap, not per integer.

Test Case 2

Input: 1 2 3 4, k = 2

Current state: there is no missing number before or between the array elements.

Action: keep moving past the last element; the missing numbers continue after 4.

Result: missing numbers are 5, 6, ... so the answer is 6.

Observation: this is the edge case where the answer lies after the last array value. Any solution that only looks for internal gaps will fail here.

Test Case 3

Input: 5 6 7, k = 2

Current state: the first gap is before the array starts. Missing numbers begin at 1.

Action: count from 1 upward until the 2nd missing number.

Result: 1, 2, 3, 4 are all missing before 5, so the answer is 2.

Observation: this shows why the beginning of the number line matters. The array does not necessarily start at 1.

The signal that should immediately trigger this approach is: “sorted array” + “kth missing / kth absent / count of gaps”. That usually means you should build a missing-count function and then search over it.

Step 5 — Optimized Solution 1 (Intermediate)

The first real optimization is to process the array gap by gap. For each adjacent pair, we compute how many positive integers are missing between them. If the kth missing number lies inside that gap, we can answer immediately. Otherwise, we subtract the whole gap and move on.

This eliminates the need to examine every integer one by one. Instead of scanning the number line, we scan only the array.

Pseudocode:

prev = 0

for each value x in arr:
    gap = x - prev - 1
    if k > gap:
        k = k - gap
        prev = x
    else:
        return prev + k

return prev + k

Time Complexity: O(n). We visit each array element once, and every gap is processed in constant time.

Space Complexity: O(1). We only use a few variables.

What was eliminated: All repeated checks of individual integers. We now jump directly over entire missing segments.

Step 5 — Optimized Solution 2 (Best Known / Fully Optimal)

The further insight is that the number of missing values before each index is monotonic. Define:

missing(i) = arr[i] - (i + 1)

Why this formula? Up to index i, there are exactly i + 1 array elements present. If the largest value is arr[i], then among the numbers 1..arr[i], the count of missing numbers is arr[i] - (i + 1).

Because the array is strictly increasing, missing(i) never decreases. That means we can binary search for the first index where missing(i) >= k.

Why start with l = 0 and r = n - 1? Because we are searching among real array indices only. The answer position may end up being n, but that is the insertion point discovered after the loop, not a valid index to inspect.

Why not search on n directly as an index? Because arr[n] does not exist. The binary search needs valid positions for the predicate, and the final answer naturally falls out of the insertion point.

Pseudocode:

l = 0
r = n - 1

while l <= r:
    mid = l + (r - l) / 2
    missing = arr[mid] - (mid + 1)

    if missing < k:
        l = mid + 1
    else:
        r = mid - 1

return l + k

C++17 Code:

int findKthPositive(vector<int>& arr, int k) {
    int n = (int)arr.size();
    int l = 0, r = n - 1;

    while (l <= r) {
        int mid = l + (r - l) / 2;
        int missing = arr[mid] - (mid + 1);  // numbers missing before arr[mid]

        if (missing < k) {
            l = mid + 1;
        } else {
            r = mid - 1;
        }
    }

    return l + k;  // insertion point + k gives the kth missing positive number
}

Dry Run 1:

Input: arr = 2 3 4 7 11, k = 5

Pivot idea: find the first index where missing(i) >= 5 

l = 0, r = 4

mid = 2
arr[2] = 4
missing = 4 - 3 = 1
1 < 5  → move right
l = 3

mid = 3
arr[3] = 7
missing = 7 - 4 = 3
3 < 5  → move right
l = 4

mid = 4
arr[4] = 11
missing = 11 - 5 = 6
6 >= 5 → move left
r = 3

Stop: l = 4
Answer = l + k = 4 + 5 = 9

Dry Run 2 (Edge Case):

Input: arr = 1 2 3 4, k = 2

Every missing(i) is 0, so no index satisfies missing(i) >= 2. 

l = 0, r = 3

mid = 1
missing = 2 - 2 = 0
0 < 2 → l = 2

mid = 2
missing = 3 - 3 = 0
0 < 2 → l = 3

mid = 3
missing = 4 - 4 = 0
0 < 2 → l = 4

Stop: l = 4
Answer = 4 + 2 = 6

This is exactly the case where the kth missing number lies after the last array element. The binary search does not need a special branch; the insertion point l = n automatically handles it.

Why the formula return l + k is correct: after the search, l is the first index where the count of missing numbers before that index is at least k. That means the answer is located just before arr[l], and among the numbers from 1 to the answer, exactly l array values are present. So the number of missing values up to the answer is answer - l, and setting that equal to k gives answer = l + k.

Time Complexity: O(log n). The missing-count function is monotonic, so binary search cuts the search space in half each step.

Space Complexity: O(1). Only a constant amount of extra memory is used.

Algorithm Name: Binary Search on the Missing Count / Lower Bound on a Monotonic Predicate.

Final Takeaway

The clean way to think about this problem is: do not search the number line directly; search the array indices using the count of missing numbers as the monotonic signal. That is the real interview insight.
