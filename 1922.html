LeetCode 1922 — Count Good Numbers

Step 1 — Problem Statement

Input: You are given a single integer n, which represents the length of a digit string. A string is considered good if digits at even indices are chosen from 0, 2, 4, 6, 8 and digits at odd indices are chosen from 2, 3, 5, 7. The indexing is zero-based, so index 0 is even.

Output: Return the number of good digit strings of length n, modulo 1,000,000,007.

Key Constraints: The value of n can be extremely large, so a direct enumeration of all strings is impossible. The answer must be computed using arithmetic structure rather than simulation.

Edge Cases: The smallest length n = 1 should work correctly. Very large values of n must not overflow. We must also handle the case where the string has only even-position slots or only one slot. Since the count grows exponentially, naive counting is infeasible.

Step 2 — Problem Understanding & Approach Overview

Strip away the story and this is really asking: how many ways can we independently choose digits for two disjoint sets of positions under fixed rules? Each even index has 5 choices, and each odd index has 4 choices, so the total count is a product of powers.

The core algorithmic challenge is to compute 5ceil(n/2) × 4floor(n/2) efficiently under a modulus. This is a mathematical counting + fast modular exponentiation problem.

Mental model: imagine the string as two independent buckets of positions. One bucket contains all even indices, the other contains all odd indices. Once you see the independence, the problem becomes pure multiplication.

The subtle trap is forgetting that indices are zero-based. Many candidates accidentally swap the counts of even and odd positions, or try brute force because the statement looks like a combinatorics puzzle.

Step 3 — Brute Force Solution

Naive idea:
Generate every possible digit string of length n.
For each string:
    check whether every even index has an even digit
    check whether every odd index has a prime digit
    if valid, increment count
Return count % MOD

This is straightforward, but completely impractical. There are 10n possible digit strings, and checking each one costs O(n).

Time Complexity: O(n × 10n) if we generate every string and verify it. The loop structure is the bottleneck: the number of candidates explodes exponentially.

Space Complexity: O(n) if we store one candidate string during generation, or O(1) if generated in-place. Either way, the time cost makes brute force unusable.

Step 4 — Intuition Building

Test Case 1

Input: n = 1
    Index 0 is even
    Even positions allow 5 digits: 0, 2, 4, 6, 8
    There are no odd positions at all
Action: Count only the even-position choices
Result: 5

This tiny case confirms the indexing rule. A naive solution that treats index 1 as the first position would fail here immediately.

Test Case 2

Input: n = 2
    Positions: 0, 1
    Position 0 is even → 5 choices
    Position 1 is odd  → 4 choices
Action: Multiply independent choices
Result: 5 × 4 = 20

This is the first case where the product structure becomes visible. No backtracking is needed because the choices at each position are independent.

Test Case 3

Input: n = 5
    Positions: 0, 1, 2, 3, 4
    Even indices: 0, 2, 4 → 3 slots → 5 choices each
    Odd indices: 1, 3     → 2 slots → 4 choices each
Action: Count each group separately and multiply
Result: 5^3 × 4^2

Here the structure is the key insight. Instead of building strings, we only need to know how many even and odd slots exist. That turns a huge search problem into a clean exponentiation problem.

A rare but important edge case is very large n. A direct power computation can overflow long long, so the final solution must use modular exponentiation.

The signal that should immediately trigger this approach in a future problem is: “independent choices per position” combined with “count the total number of valid assignments”. That usually means multiplication of per-position counts and fast exponentiation.

Step 5 — Optimized Solution

There is only one meaningful optimal solution here: use the counting formula directly and compute the powers with fast modular exponentiation. No intermediate optimization level is really necessary.

The count of even positions in a zero-based string of length n is (n + 1) / 2. The count of odd positions is n / 2. Therefore: 

answer = 5^((n + 1) / 2) * 4^(n / 2) mod 1,000,000,007

This formula is the whole problem. The only remaining work is computing powers efficiently.

Why the formula is correct

Every even index can be filled independently with one of 5 valid digits. Every odd index can be filled independently with one of 4 valid digits. Because these choices do not affect each other, the multiplication principle applies.

The exponent for even indices is (n + 1) / 2 because the sequence of indices starts at 0: for example, for n = 5, the even indices are 0, 2, 4, which is 3 positions. The exponent for odd indices is n / 2: for n = 5, the odd indices are 1, 3, which is 2 positions.

Why modular exponentiation is necessary

Even a modest power like 5100 is far beyond normal integer range. So we repeatedly square the base and reduce modulo 1,000,000,007 at every step. This keeps values bounded and makes the solution fast.

Interview-ready C++17 code

int countGoodNumbers(long long n) {
    const long long MOD = 1000000007LL;

    auto modPow = [&](long long base, long long exp) -> long long {
        long long result = 1;
        base %= MOD;

        while (exp > 0) {
            if (exp & 1LL) {
                result = (result * base) % MOD;
            }
            base = (base * base) % MOD;
            exp >>= 1LL;
        }

        return result;
    };

    long long evenPositions = (n + 1) / 2;
    long long oddPositions = n / 2;

    long long waysEven = modPow(5, evenPositions);
    long long waysOdd = modPow(4, oddPositions);

    return (int)((waysEven * waysOdd) % MOD);
}

Dry Run

Input: n = 5

Step 1: Count positions
    evenPositions = (5 + 1) / 2 = 3
    oddPositions  = 5 / 2 = 2

Step 2: Compute powers
    waysEven = 5^3 = 125
    waysOdd  = 4^2 = 16

Step 3: Multiply
    answer = 125 × 16 = 2000

Step 4: Apply modulo
    2000 % 1,000,000,007 = 2000

Final Result: 2000

Extreme Edge Case Handling

Input: n = 1

Step 1: Count positions
    evenPositions = (1 + 1) / 2 = 1
    oddPositions  = 1 / 2 = 0

Step 2: Compute powers
    waysEven = 5^1 = 5
    waysOdd  = 4^0 = 1

Step 3: Multiply
    answer = 5 × 1 = 5

Final Result: 5

This shows why the empty odd-position group must contribute 1, not 0. Multiplicative identity matters here. A beginner mistake is to treat “no odd positions” as “zero ways,” which would incorrectly force the whole answer to zero.

Complexity Analysis

Time Complexity: O(log n). Each modular exponentiation uses repeated squaring, which halves the exponent on every iteration. We perform it twice, so the total is still O(log n).

Space Complexity: O(1). The algorithm uses only a few variables and no recursion.

What a strong candidate should notice instantly

The key signal is not “digit string” but “each position has a fixed number of independent choices.” That is almost always a counting problem, and counting problems with huge exponents almost always need modular exponentiation.
