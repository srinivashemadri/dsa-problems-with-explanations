LeetCode 494 — Target Sum

LeetCode 494 asks for the number of ways to assign a + or - sign to every number in the array so that the final expression equals the given target. This is a counting problem, not a decision problem, and the key insight is to convert sign assignment into a subset-counting problem. Step 1 — Problem Statement

Input: You are given an integer array nums of non-negative integers and an integer tagger. For each number, you must choose either a plus or a minus sign.

Output: Return the number of different sign assignments whose total equals tagger.

Key Constraints: The array length is small enough for dynamic programming, typically n ≤ 20, and the total sum of all values is bounded, typically ∑ nums[i] ≤ 1000. That matters because the brute-force search space is still exponential, but the sum-based DP is very manageable.

Edge Cases:

  • All elements are zero. Every zero can be marked + or -, and both choices are distinct assignments.
  • Single-element arrays, especially when the element equals the target or its negative.
  • Targets outside the reachable range, where |target| > total sum.
  • Cases where no assignment works, even though the numbers are small.

Step 2 — Problem Understanding & Approach Overview

Strip away the story: this is asking, how many ways can we split the array into two groups so that one group is added and the other is subtracted, and the difference becomes the target?

The core challenge is not finding one valid expression; it is counting all valid expressions without enumerating every sign pattern.

This is a classic counting DP / subset-sum / 0-1 knapsack problem.

Mental model: think of every number as a decision point. A + means the number goes into the positive bucket, and a - means it goes into the negative bucket. The final value is the difference between these two buckets.

Subtle trap: many candidates forget that 0 is special. Both +0 and -0 keep the sum unchanged, but they are still two different assignments, so each zero doubles the count.

Step 3 — Brute Force Solution

The most direct solution is to try both signs for every number and count how many complete assignments hit the target. 

function solve(i, currentSum):
    if i == n:
        if currentSum == target:
            return 1
        return 0

    plusWays  = solve(i + 1, currentSum + nums[i])
    minusWays = solve(i + 1, currentSum - nums[i])

    return plusWays + minusWays

Time Complexity: O(2^n). Each index branches into two choices, so the recursion tree has two leaves per level.

Space Complexity: O(n) for the recursion stack.

Performance bottleneck: many different sign paths reach the same (index, currentSum) state, so the same subproblem is recomputed again and again.

Step 4 — Intuition Building

Test Case 1

Input: nums = [1], target = 1
    Only two assignments exist:
    +1 = 1
    -1 = -1

Action: Count assignments that equal target

Result: 1 way

Test Case 2

Input: nums = [1, 1], target = 0
    Possible assignments:
    +1 +1 = 2
    +1 -1 = 0
    -1 +1 = 0
    -1 -1 = -2

Action: Count the valid zero-sum assignments

Result: 2 ways

Observation:
    The same total can be reached by different sign patterns.
    So this is not a shortest-path problem or a boolean existence problem.
    It is a counting problem.

Test Case 3 (Edge Case)

Input: nums = [0, 0, 0, 0, 1], target = 1
    Each zero has two valid sign choices:
    +0 and -0
    Both keep the sum unchanged, but both count as different assignments.

Action:
    Fix the 1 as +1
    Then each of the 4 zeros independently doubles the number of ways

Result: 2^4 = 16 ways

Why brute force feels wasteful:
    It explores the same sum state repeatedly for every zero,
    even though the only effect is doubling the count.

This is the point where the hidden structure becomes visible: instead of thinking about signs directly, think about the set of numbers chosen to be positive. If the total sum of all numbers is S, and the positive bucket sums to P, then the negative bucket sums to S - P. The final expression becomes P - (S - P) = target, so 2P = S + target. That converts the problem into counting subsets with sum (S + target) / 2.

Signal to remember for future problems: whenever you see +/- assignments, difference between two groups, or counting ways to reach a target, immediately think of subset-sum counting.

Step 5 — Optimized Solution 1 (Intermediate)

The first optimization is to memoize the brute-force recursion. The state is (index, currentSum). This removes repeated work because the same state may be reached through different sign paths. 

memoize(i, currentSum):
    if i == n:
        return 1 if currentSum == target else 0

    if state (i, currentSum) is already computed:
        return stored value

    ans = memoize(i + 1, currentSum + nums[i]) 
        + memoize(i + 1, currentSum - nums[i])

    store and return ans

Since currentSum can be negative, we usually use an offset based on the total sum, so the DP table size stays finite.

Time Complexity: O(n × range), where range is the number of possible sums. With the standard constraints, the total sum is at most about 1000, so the state space is small.

Space Complexity: O(n × range) for the memo table plus O(n) recursion stack.

What was eliminated: repeated recomputation of identical subproblems.

Step 5 — Optimized Solution 2 (Best Known / Fully Optimal)

The deeper insight is to remove the sign dimension entirely. Let the total sum be S. If the positive subset sums to P, then the negative subset sums to S - P. We need: 

P - (S - P) = target
2P = S + target
P = (S + target) / 2

So the problem becomes: count the number of subsets whose sum is (S + target) / 2.

This is a standard 0/1 knapsack counting problem.

Important validity checks: if |target| > S, there is no way to reach the target. If S + target is odd, the required subset sum is not an integer, so the answer is also zero. 

function findTargetSumWays(nums, target):
    S = sum of nums

    if abs(target) > S:
        return 0

    if (S + target) is odd:
        return 0

    need = (S + target) / 2

    dp[0..need] = 0
    dp[0] = 1

    for each x in nums:
        for s from need down to x:
            dp[s] += dp[s - x]

    return dp[need]
  
int findTargetSumWays(vector<int>& nums, int target) {
    int total = 0;
    for (int x : nums) total += x;

    if (abs(target) > total) return 0;

    int sumPlusTarget = total + target;
    if (sumPlusTarget % 2 != 0) return 0;

    int need = sumPlusTarget / 2;
    vector<long long> dp(need + 1, 0);
    dp[0] = 1;

    for (int x : nums) {
        for (int s = need; s >= x; --s) {
            dp[s] += dp[s - x];
        }
    }

    return (int)dp[need];
}

Time Complexity: O(n × need), where need = (S + target) / 2. Since S ≤ 1000, this is comfortably efficient.

Space Complexity: O(need) using the 1D DP array.

Why this is the best form: it compresses the whole sign-assignment problem into a clean subset-counting DP, while still handling zeros correctly and avoiding the exponential explosion of brute force.
