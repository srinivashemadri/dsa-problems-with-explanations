LeetCode 31 — Next Permutation
Step 1 — Problem Statement

Input: An integer array nums, where the goal is to rearrange the numbers into the next lexicographically larger permutation of the same multiset of values. If no such larger permutation exists, the array must become the smallest possible permutation.

Output: Modify the array in place so that it becomes the next permutation.

Key Constraints: The operation must be done in-place with constant extra space, and the result must be the next arrangement in lexicographic order, not just any larger arrangement. Duplicates are allowed, so the logic must work even when equal values appear.

Edge Cases: empty array, single element, strictly increasing order, strictly decreasing order, all elements equal, repeated values, and pivots near the end of the array.

Step 2 — Problem Understanding & Approach Overview

This problem is really asking: given the current permutation, find the smallest permutation that is still greater than it. In other words, move to the next lexicographic arrangement.

The core challenge is to change the array as little as possible while still making it larger.

Category: array manipulation, greedy, permutation logic.

Mental Model: think of the array like a number written digit by digit. To get the next number, you try to increase it from the right side first, because changing the right side keeps the increase minimal.

Subtle Trap: many candidates try to sort the whole array or scan from the left. That either becomes too slow or gives the wrong permutation. The key is to find the first position from the right where the order stops being descending.

Step 3 — Brute Force Solution

The naive idea is to generate every permutation, sort them lexicographically, and pick the one right after the current array. That is conceptually simple but completely impractical. 

Pseudocode:

1. Generate all permutations of nums.
2. Sort all permutations lexicographically.
3. Find the current permutation in that list.
4. Return the next one if it exists; otherwise return the first permutation.

Why this works:
- It explicitly constructs the permutation order.
- The answer is literally the next element in sorted order.

Time Complexity:
- There are n! permutations.
- Sorting them adds extra cost.
- Overall complexity is far too large: O(n! * n log(n!)) in practice, or worse depending on implementation.

Space Complexity:
- O(n! * n) if all permutations are stored.
- This is the main bottleneck.

Performance Bottleneck:
- The explosion in the number of permutations makes this unusable even for moderate n.
Step 4 — Intuition Building

Test Case 1

Input: 1 2 3
    Current order is increasing.
    Scan from right: 2 < 3, so pivot = 2.
    We only need the smallest increase, so swap pivot with the next greater element in the suffix.

Action: Swap 2 and 3
Result: 1 3 2

Test Case 2

Input: 3 2 1
    Entire array is decreasing.
    There is no pivot because no position satisfies nums[i] < nums[i + 1].
    This means the current permutation is the highest possible permutation.

Action: Reverse entire array
Result: 1 2 3

Test Case 3

Input: 1 5 1
    Scan from right:
      5 > 1, keep moving left.
      1 < 5, pivot = first 1.
    Suffix is 5 1, which is decreasing.
    We need the smallest element in the suffix that is greater than pivot.

Action:
    Swap pivot 1 with 5
    Reverse suffix after pivot

Result: 5 1 1

The inefficiency in brute force is obvious here: we do not need all permutations. We only need to change the array at the first place from the right where it can still become larger, then make the suffix as small as possible.

The key insight is this: the suffix to the right of the pivot is already in descending order. That means it is the largest arrangement of those suffix elements. Once we choose a larger element for the pivot, the best way to get the next permutation is to turn the suffix into its smallest arrangement, which is ascending order.

A rare edge case that often gets missed is an array with duplicates, such as 1 1 5 or 1 5 1. The same pivot logic still works because we only care about strict inequality for the pivot and then choose the next larger element from the suffix.

The signal that should immediately trigger this approach in future problems is: “find the next lexicographic arrangement with minimum possible change, in-place.”

Step 5 — Optimized Solution

There is one optimal solution here: a greedy one-pass scan from right to left, followed by a swap and a suffix reversal. This is the standard in-place next permutation algorithm.

Idea

Find the first index i from the right such that nums[i] < nums[i + 1]. That index is the pivot. Then find the smallest number in the suffix that is greater than nums[i], swap them, and reverse the suffix after i.

Pseudocode

1. Find the pivot:
   Start from the second last index and move left while nums[i] >= nums[i + 1].

2. If pivot does not exist:
   Reverse the entire array and stop.

3. Find the rightmost element greater than nums[pivot].

4. Swap nums[pivot] with that element.

5. Reverse the suffix from pivot + 1 to end.

Full Working C++17 Code

void nextPermutation(vector<int>& nums) {
    int n = nums.size();
    if (n <= 1) return;

    int i = n - 2;

    while (i >= 0 && nums[i] >= nums[i + 1]) {
        --i;
    }

    if (i < 0) {
        reverse(nums.begin(), nums.end());
        return;
    }

    int j = n - 1;
    while (nums[j] <= nums[i]) {
        --j;
    }

    swap(nums[i], nums[j]);
    reverse(nums.begin() + i + 1, nums.end());
}

Dry Run

Input: 1 3 5 4 2

Pivot Search:
    4 > 2  → keep moving left
    5 > 4  → keep moving left
    3 < 5  → pivot = 3

Rightmost Element Greater Than Pivot:
    Scan from the end:
      2 <= 3
      4 > 3  → choose 4

Swap:
    1 4 5 3 2

Reverse Suffix After Pivot:
    Suffix = 5 3 2
    Reverse suffix → 2 3 5

Final Result:
    1 4 2 3 5

Extreme Edge Case Dry Run

Input: 3 2 1

Pivot Search:
    2 > 1
    3 > 2
    No pivot found

Action:
    Reverse entire array

Final Result:
    1 2 3

Why This Is Correct

The first place from the right where the order can be increased is the pivot. Changing anything further left would create a bigger jump than necessary. Among all larger choices for the pivot, the rightmost greater element in the suffix gives the smallest possible increase. Finally, reversing the suffix makes it the smallest possible arrangement, which ensures the total result is the next lexicographic permutation and not just some larger one.

Complexity Analysis

Time Complexity: O(n). The array is scanned from right to left to find the pivot, scanned again to find the swap candidate, and the suffix is reversed once. Each step is linear.

Space Complexity: O(1). The work is done in-place, using only a few variables.
