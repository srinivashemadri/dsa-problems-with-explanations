LeetCode 2104 — Sum of Subarray Ranges

Step 1 — Problem Statement

Input: an integer array nums. A subarray means any contiguous slice of that array.

Output: the sum, over every subarray, of max(subarray) - min(subarray).

Key Constraints: the array can contain duplicates and negative values, so the solution must handle ties correctly. The values can be large enough that the final answer should be stored in 64-bit arithmetic.

Edge Cases:

  • A single element array gives 0, because every subarray has max = min.
  • All elements equal also gives 0.
  • Strictly increasing or strictly decreasing arrays still need careful handling because many subarrays share the same max or min.
  • Duplicates are the subtle trap: a subarray with repeated max/min values must be counted exactly once, not twice.
  • Large values require long long to avoid overflow.

Step 2 — Problem Understanding & Approach Overview

This is not really asking for anything about “ranges” as a geometric object. It is asking for the total spread of every contiguous interval. For each subarray, compute the largest value and the smallest value, subtract them, and add that difference to the answer.

The core algorithmic challenge is avoiding repeated work. A naive solution recomputes max and min for the same elements again and again across overlapping subarrays.

Category: subarray / contribution counting / monotonic stack.

Mental model: instead of asking, “what is the max and min of each subarray?”, ask, “for how many subarrays is this element the maximum, and for how many subarrays is it the minimum?” Once you know that, each element’s contribution can be counted directly.

Common trap: handling duplicates incorrectly. If you use the same strictness on both sides of a monotonic boundary, you either overcount or undercount equal values.

Step 3 — Brute Force Solution

The most direct solution is to enumerate every subarray, scan it to find the minimum and maximum, and add the difference. That is correct, but it repeats the same comparisons many times. 

answer = 0
for l from 0 to n - 1:
    for r from l to n - 1:
        curMin = +infinity
        curMax = -infinity
        for k from l to r:
            curMin = min(curMin, nums[k])
            curMax = max(curMax, nums[k])
        answer += curMax - curMin
return answer

Time Complexity: O(n^3). There are O(n^2) subarrays, and each one may scan up to O(n) elements.

Space Complexity: O(1).

Bottleneck: the inner scan for every subarray. The same elements get rescanned over and over.

Step 4 — Intuition Building

Test Case 1

Input: 1 2 3
    Subarrays:
    [1] -> range 0
    [1,2] -> range 1
    [1,2,3] -> range 2
    [2] -> range 0
    [2,3] -> range 1
    [3] -> range 0

Action:
    Compute every subarray directly and add all ranges.

Result:
    Total = 0 + 1 + 2 + 0 + 1 + 0 = 4

Observation: the same values participate in many overlapping subarrays. That repeated work is exactly what we want to eliminate.

Test Case 2

Input: 2 2
    Subarrays:
    [2] -> range 0
    [2,2] -> range 0
    [2] -> range 0

Action:
    The answer is still 0, but duplicates expose the real issue:
    if both equal 2s try to claim the same subarray as the maximum or minimum,
    the counting logic breaks.

Result:
    Total = 0

This is the key insight: when counting contributions, one side must be strict and the other side must be non-strict. That guarantees equal values are assigned consistently to exactly one index.

Test Case 3

Input: 3 1 2
    Subarrays:
    [3] -> 0
    [3,1] -> 2
    [3,1,2] -> 2
    [1] -> 0
    [1,2] -> 1
    [2] -> 0

Action:
    The maximum and minimum of overlapping windows are not independent.
    The same element keeps reappearing as max or min across many intervals.

Result:
    Total = 5

This is where the problem starts to look like a contribution problem: each element should be counted by how many subarrays it dominates as max or min.

What signal should make you think of this approach immediately? Any time a problem asks for a total over all subarrays or intervals, and each interval’s answer depends on min/max, think about element-wise contribution counting with monotonic stacks.

Step 5 — Optimized Solution 1 (Intermediate)

A natural improvement over brute force is to fix the left boundary and expand the right boundary while maintaining the running minimum and maximum. When the right end moves one step, min and max can be updated in O(1). 

answer = 0
for l from 0 to n - 1:
    curMin = +infinity
    curMax = -infinity
    for r from l to n - 1:
        curMin = min(curMin, nums[r])
        curMax = max(curMax, nums[r])
        answer += curMax - curMin
return answer

Time Complexity: O(n^2). The outer loop chooses the left boundary, and the inner loop walks the right boundary once.

Space Complexity: O(1).

What was eliminated: the extra scan inside each subarray. We still examine all subarrays, but we no longer recompute min and max from scratch for each one.

Step 5 — Optimized Solution 2 (Best Known / Fully Optimal)

The fully optimal idea is to count contributions. The total answer is:
sum of all subarray maximum contributions minus sum of all subarray minimum contributions.

For each index i, count how many subarrays choose nums[i] as the maximum. The same is done for minimum. The count is a product of:
number of choices for the left boundary × number of choices for the right boundary.

For maxima, use:
previous strictly greater element on the left,
next greater-or-equal element on the right.

For minima, use:
previous strictly smaller element on the left,
next smaller-or-equal element on the right.

That strict / non-strict asymmetry is the tie-break rule that prevents duplicate values from being counted twice. One equal value “owns” the subarray, and the other does not.

Pseudocode:

1. Compute previous greater element index for every position.
2. Compute next greater-or-equal element index for every position.
3. Compute previous smaller element index for every position.
4. Compute next smaller-or-equal element index for every position.
5. For each i:
       maxContribution = nums[i] * (i - prevGreater[i]) * (nextGreaterEq[i] - i)
       minContribution = nums[i] * (i - prevSmaller[i]) * (nextSmallerEq[i] - i)
6. Return sum(maxContribution) - sum(minContribution)

C++17 Code:

long long subArrayRanges(vector<int>& nums) {
    int n = (int)nums.size();
    vector<int> prevGreater(n), nextGreaterEq(n), prevSmaller(n), nextSmallerEq(n);
    stack<int> st;

    // Previous greater (strictly greater)
    for (int i = 0; i < n; ++i) {
        while (!st.empty() && nums[st.top()] <= nums[i]) st.pop();
        prevGreater[i] = st.empty() ? -1 : st.top();
        st.push(i);
    }

    while (!st.empty()) st.pop();

    // Next greater or equal
    for (int i = n - 1; i >= 0; --i) {
        while (!st.empty() && nums[st.top()] < nums[i]) st.pop();
        nextGreaterEq[i] = st.empty() ? n : st.top();
        st.push(i);
    }

    while (!st.empty()) st.pop();

    // Previous smaller (strictly smaller)
    for (int i = 0; i < n; ++i) {
        while (!st.empty() && nums[st.top()] >= nums[i]) st.pop();
        prevSmaller[i] = st.empty() ? -1 : st.top();
        st.push(i);
    }

    while (!st.empty()) st.pop();

    // Next smaller or equal
    for (int i = n - 1; i >= 0; --i) {
        while (!st.empty() && nums[st.top()] > nums[i]) st.pop();
        nextSmallerEq[i] = st.empty() ? n : st.top();
        st.push(i);
    }

    long long maxSum = 0, minSum = 0;

    for (int i = 0; i < n; ++i) {
        long long leftMax = i - prevGreater[i];
        long long rightMax = nextGreaterEq[i] - i;
        maxSum += 1LL * nums[i] * leftMax * rightMax;

        long long leftMin = i - prevSmaller[i];
        long long rightMin = nextSmallerEq[i] - i;
        minSum += 1LL * nums[i] * leftMin * rightMin;
    }

    return maxSum - minSum;
}

    16 - 12 = 4

Why this handles the all-equal edge case correctly: if the array is 5 5 5, every subarray has max = min, so the answer must be 0. With the strict/non-strict boundary choice, the max and min contributions are both counted consistently and cancel out exactly.

Time Complexity: O(n). Each index is pushed and popped at most once in each monotonic scan, so all four boundary passes are linear, and the final contribution pass is also linear.

Space Complexity: O(n). We store four boundary arrays and a stack.

Algorithm name: monotonic stack contribution counting.

Final Interview-Ready Summary

The brute-force way is to inspect every subarray and compute its min and max directly. The stronger idea is to realize that every element contributes to many subarrays as the minimum or maximum. Once you count those contributions with monotonic stacks, the answer becomes linear.

The subtle part is tie-handling for duplicates. Choose one side strict and the other side non-strict, and keep that rule consistent for both minima and maxima.
