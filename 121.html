LeetCode 121 — Best Time to Buy and Sell Stock
Step 1 — Problem Statement

Input: You are given an array prices, where prices[i] is the price of a given stock on day i. You are allowed to complete at most one transaction: buy one share on one day and sell it on a later day.

Output: Return the maximum profit you can achieve. If no profit is possible, return 0.

Key Constraints: The sell day must be strictly after the buy day. Only one buy and one sell are allowed. The answer is never negative because you can always choose not to trade.

Edge Cases: an empty or single-element array, a strictly decreasing array, a strictly increasing array, all equal prices, and very large inputs where an O(n^2) approach becomes too slow. This is the classic one-transaction stock profit problem, and it appears in your requested workflow as a LeetCode solution task. :contentReference[oaicite:0]{index=0}

Step 2 — Problem Understanding & Approach Overview

What this problem is really asking is: among all pairs of days, choose one earlier day to buy and one later day to sell so that the difference is maximum. The story is just packaging; the core task is finding the best difference prices[sell] - prices[buy] with sell > buy.

This is a single-pass greedy / prefix-min problem. The mental model is simple: as you scan left to right, keep track of the lowest price seen so far, because that is the best possible buy price for the current day. The subtle trap is trying to compare every pair or updating the minimum at the wrong time. Another common mistake is assuming you must buy and sell even when every trade loses money; the correct answer is still 0.

Step 3 — Brute Force Solution

Try every possible buy day and every possible sell day after it, then compute the profit for each pair.

maxProfit = 0 for buy from 0 to n - 1: for sell from buy + 1 to n - 1: profit = prices[sell] - prices[buy] if profit > maxProfit: maxProfit = profit return maxProfit

Each buy day is paired with all later sell days. That guarantees correctness because every valid transaction is checked.

Time Complexity: O(n²). The outer loop runs n times, and the inner loop can run up to n times for each outer iteration.

Space Complexity: O(1). Only a few variables are used.

The bottleneck is the pairwise comparison of all possible transactions.

Step 4 — Intuition Building
Test Case 1
Input: 7 1 5 3 6 4
Current state: no decision yet, but the first useful observation is that 1 is a better buy price than 7.
Action: track the minimum price seen so far and compare every day against it.
Result: best profit becomes 5 by buying at 1 and selling at 6.
Test Case 2
Input: 7 6 4 3 1
Current state: every new price is lower than the previous minimum.
Action: keep updating the minimum, but no sell day ever produces positive profit.
Result: 0, because the best choice is to do nothing.
Test Case 3
Input: 1 2 3 4 5
Current state: the first day is already the cheapest seen so far.
Action: hold that minimum and keep checking future days; each day improves the profit.
Result: 4 by buying at 1 and selling at 5.

The inefficiency in brute force is obvious here: for every day, you repeatedly ask the same question about earlier prices. The key structure is that for any sell day, only the smallest previous price matters. You do not need all previous prices, only the best buy candidate so far.

A rare but important edge case is a fully decreasing array. A naive approach might still try to force a transaction, but the optimal logic naturally returns 0 because the running best profit never becomes positive.

The moment you see a problem asking for the best pair with an ordering constraint like earlier index, later index, and the score is a difference, you should immediately think: track the prefix minimum while scanning once.

Step 5 — Optimized Solution

This problem has one clear optimal solution: a single pass with a running minimum. That is the fully optimal approach, so there is no separate second optimization tier needed here.

Idea: As you scan from left to right, maintain the lowest price seen so far. For each day, treat that day as a possible sell day and compute the profit if you had bought at the best earlier price. Update the answer, then update the minimum if the current price is lower.

Algorithm Name: Prefix Minimum / One-pass Greedy.

int maxProfit(vector<int>& prices) { int minPrice = INT_MAX; int best = 0; for (int price : prices) { if (price < minPrice) { minPrice = price; } else { best = max(best, price - minPrice); } } return best; }

Why this works: For each day, the best possible buy day among all earlier days is simply the smallest price seen so far. If you sell today, the best profit is therefore current price - running minimum. Taking the maximum over all days yields the global answer.

Final Result: 5

Handling the extreme edge case: for a decreasing array like 7 6 4 3 1, the running minimum keeps dropping, but no day ever beats it as a sell day. The answer stays 0, which is exactly correct.

Time Complexity: O(n). Each price is processed exactly once, and all work inside the loop is constant time.

Space Complexity: O(1). Only two integers are stored: the running minimum and the best profit.
