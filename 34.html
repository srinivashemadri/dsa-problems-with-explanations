LeetCode 34 — Find First and Last Position of Element in Sorted Array
Step 1 — Problem Statement

Input: A sorted array of integers nums in non-decreasing order and an integer target.
Output: Return the starting and ending index of target in the array. If target does not exist, return [-1, -1].
Key Constraints: The array is already sorted, so the ordering information is the main clue. Duplicates may exist, and the target can appear multiple times or not at all.
Edge Cases: empty array, single element, target absent, target appears once, target appears many times, target only at the beginning or end, all elements equal, and the case where the whole array is the target.

Step 2 — Problem Understanding & Approach Overview

This is really asking for the leftmost and rightmost occurrence of a value in a sorted array. The core challenge is not finding any occurrence, but finding both boundaries efficiently.
Category: Binary Search on boundaries.
Mental model: because the array is sorted, the target values form one contiguous block, and binary search can be used to find the block’s left edge and right edge separately.
Common trap: find one target using binary search and then expand linearly left and right. That works functionally, but it loses the logarithmic advantage and becomes O(n) in the worst case.

Step 3 — Brute Force Solution

The naive approach is simple: scan the whole array, remember the first index where nums[i] == target, and keep updating the last index whenever the target appears again. 

first = -1
last = -1

for i from 0 to n - 1:
    if nums[i] == target:
        if first == -1:
            first = i
        last = i

return [first, last]

Time Complexity: O(n) because every element may be checked once.
Space Complexity: O(1) because only a few variables are used.
Bottleneck: we ignore the fact that the array is sorted, so we do unnecessary full traversal even though binary search can isolate the range much faster.

Step 4 — Intuition Building

Test Case 1

Input: nums = [5, 7, 7, 8, 8, 10], target = 8
    Target appears in a block: indices 3 and 4
Action: Find the left boundary first, then the right boundary
Result: [3, 4]

Test Case 2

Input: nums = [5, 7, 7, 8, 8, 10], target = 6
    Target is absent, but the sorted order still lets us rule out halves quickly
Action: Binary search never finds a valid boundary
Result: [-1, -1]

Test Case 3 (Edge Case)

Input: nums = [2, 2, 2, 2], target = 2
    Entire array is one contiguous target block
    A linear expansion solution would still work, but it wastes the sorted property
Action: Left boundary becomes 0, right boundary becomes 3
Result: [0, 3]

The key insight is that the target range is contiguous because the array is sorted. So instead of searching for the value itself, we search for the first position where the value could appear and the first position after the value stops appearing.
Signal to remember: whenever a sorted array asks for the first, last, lower bound, or range of something, think of boundary binary search immediately. :contentReference[oaicite:0]{index=0}

Step 5 — Optimized Solution

This problem has one meaningful optimized approach: use two binary searches, one for the left boundary and one for the right boundary.

The first search finds the leftmost index where target could be placed without breaking order. The second search finds the rightmost index by searching for the first index greater than target and subtracting 1.

Optimized Idea

Search for the lower bound of target, then search for the lower bound of target + 1 and step back by one. This cleanly identifies the full range of equal values.

Pseudocode

function lowerBound(nums, x):
    left = 0
    right = nums.size()

    while left < right:
        mid = left + (right - left) / 2
        if nums[mid] < x:
            left = mid + 1
        else:
            right = mid

    return left

function searchRange(nums, target):
    leftIndex = lowerBound(nums, target)
    if leftIndex == nums.size() or nums[leftIndex] != target:
        return [-1, -1]

    rightIndex = lowerBound(nums, target + 1) - 1
    return [leftIndex, rightIndex]

Full Working C++17 Code

vector<int> searchRange(vector<int>& nums, int target) {
    auto lowerBound = [&](int x) {
        int left = 0, right = (int)nums.size();
        while (left < right) {
            int mid = left + (right - left) / 2;
            if (nums[mid] < x) {
                left = mid + 1;
            } else {
                right = mid;
            }
        }
        return left;
    };

    int leftIndex = lowerBound(target);
    if (leftIndex == (int)nums.size() || nums[leftIndex] != target) {
        return {-1, -1};
    }

    int rightIndex = lowerBound(target + 1) - 1;
    return {leftIndex, rightIndex};
}

Dry Run

Input: nums = [5, 7, 7, 8, 8, 10], target = 8

Left Boundary Search
Pivot idea: find first index where value is not less than 8
left = 0, right = 6
mid = 3, nums[3] = 8 → move right to 3
left = 0, right = 3
mid = 1, nums[1] = 7 < 8 → move left to 2
left = 2, right = 3
mid = 2, nums[2] = 7 < 8 → move left to 3
Stop: leftIndex = 3

Right Boundary Search
Search for first index where value is not less than 9
left = 0, right = 6
mid = 3, nums[3] = 8 < 9 → move left to 4
left = 4, right = 6
mid = 5, nums[5] = 10 ≥ 9 → move right to 5
left = 4, right = 5
mid = 4, nums[4] = 8 < 9 → move left to 5
Stop: lowerBound(9) = 5, so rightIndex = 5 - 1 = 4

Final Result: [3, 4]

Extreme Edge Case Handling

For nums = [2, 2, 2, 2], target = 2:
leftIndex = 0 because the first valid position is the beginning.
lowerBound(3) = 4, so rightIndex = 3.
Final Result: [0, 3]

Time Complexity: O(log n) because each lower-bound search halves the search space, and we run it twice.
Space Complexity: O(1) because the solution uses only a few pointers and no extra data structure.
Name of the technique: Boundary Binary Search / Lower Bound Search.
