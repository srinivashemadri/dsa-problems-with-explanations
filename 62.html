Step 1 — Problem Statement

Input: You are given two integers m and n, which represent the number of rows and columns in a grid. A robot starts at the top-left cell and wants to reach the bottom-right cell. On each move, it may only go right or down.

Output: Return the number of distinct paths from the top-left corner to the bottom-right corner.

Key Constraints: Every valid path has exactly m - 1 downward moves and n - 1 rightward moves. The order of those moves is what creates different paths. This means the problem is fundamentally a counting problem, not a shortest-path problem.

Edge Cases: A one-row grid or a one-column grid has exactly one path, because there is only one possible direction to move. The smallest grid, 1 x 1, also has exactly one path: the robot is already at the destination. A common trap is forgetting that different move orders count as different paths even though the total number of moves is the same.

Step 2 — Problem Understanding & Approach Overview

This problem is really asking: in how many different ways can we arrange a fixed number of right moves and down moves? The story is just a grid wrapper around a counting structure.

The core algorithmic challenge is that a naive recursive solution recomputes the same subproblems many times. This is a classic Dynamic Programming problem.

The mental model should be: every cell collects paths from the cell above and the cell to the left. Once you see that, the grid becomes a table of accumulated counts.

The subtle trap is to think in terms of “all possible route shapes” and branch recursively without remembering results. That explodes into repeated work very quickly.

Step 3 — Brute Force Solution

The most direct idea is to recursively move right or down until reaching the destination. If we go out of bounds, that path contributes zero. If we reach the bottom-right cell, that path contributes one. 

function dfs(i, j):
    if i == m - 1 and j == n - 1:
        return 1
    if i >= m or j >= n:
        return 0

    rightWays = dfs(i, j + 1)
    downWays  = dfs(i + 1, j)

    return rightWays + downWays

answer = dfs(0, 0)

Time Complexity: O(2^(m+n)) in the recursion-tree sense, because each state branches into two choices and the same subproblems are revisited many times. A more precise way to see the explosion is that the number of distinct paths itself is combinatorial, and brute force explores an exponentially large tree.

Space Complexity: O(m+n) for the recursion stack, because the deepest path can move at most m - 1 times down and n - 1 times right.

Performance Bottleneck: The same cell is solved again and again from different parent paths. For example, the count of paths to a middle cell can be recomputed many times.

Step 4 — Intuition Building

Test Case 1

Input: 1 x 1

Only one cell exists. The robot starts at the destination, so no movement is needed.

Action: Return 1 immediately.

Result: 1

Test Case 2

Input: 2 x 2

A valid path must contain one right move and one down move. The only difference is the order.

Action: Count the move arrangements: RD and DR.

Result: 2

Test Case 3

Input: 3 x 7

Every path has exactly 2 down moves and 6 right moves. A brute force recursion would repeatedly count the same inner cells from many routes.

Observation: The number of ways to reach any cell depends only on the cell above it and the cell to its left. That means each cell can store its answer once.

Action: Build the answer row by row using previous counts instead of exploring every route separately.

Result: The answer grows through a stable pattern instead of repeated recursion.

Extreme Edge Case: For any 1 x n or m x 1 grid, the optimal method must still return 1. A naive recursion handles this only after exploring the structure; the DP solution gets it naturally from the base row/column initialization.

Signal for the future: When a problem asks for the number of ways to reach a destination using only restricted monotonic moves, think about a grid DP where each state is the sum of its direct predecessors.

Step 5 — Optimized Solution 1 (Intermediate): 2D DP

The first optimization is to store the answer for each cell exactly once. Let dp[i][j] be the number of unique paths to cell (i, j). Then:
dp[i][j] = dp[i - 1][j] + dp[i][j - 1]
because every path to (i, j) must come either from above or from the left. 

Initialize a 2D table dp[m][n]

For every cell in the first row:
    dp[0][j] = 1

For every cell in the first column:
    dp[i][0] = 1

For i from 1 to m - 1:
    For j from 1 to n - 1:
        dp[i][j] = dp[i - 1][j] + dp[i][j - 1]

Return dp[m - 1][n - 1]

Time Complexity: O(mn), because every cell is filled once.

Space Complexity: O(mn), because the full table is stored.

What was eliminated: All repeated recursive recomputation. Each subproblem is solved once and reused.

Step 5 — Optimized Solution 2 (Best Known / Fully Optimal): 1D DP

The further insight is that to compute the current row, you do not need the entire grid. You only need the previous row values and the current row being built. That lets us compress the 2D table into one array.

Here, dp[j] means: number of ways to reach column j in the current row. Before updating dp[j], it still holds the value from the row above. After updating, it becomes the current row value. 

int uniquePaths(int m, int n) {
    vector dp(n, 1);

    for (int i = 1; i < m; ++i) {
        for (int j = 1; j < n; ++j) {
            dp[j] += dp[j - 1];
        }
    }

    return static_cast(dp[n - 1]);
}

Dry Run: Take m = 3, n = 7.

Final Result: 28

Edge Case Handling: For 1 x n, the outer loop never runs and the answer stays 1. For m x 1, the inner loop never runs and the answer also stays 1. The initialization already captures the correct base case.

Time Complexity: O(mn), because every cell's value is computed once through a constant-time update.

Space Complexity: O(n), because only one row of DP state is stored.

Algorithm Name: Dynamic Programming with State Compression.

Final Takeaway

The key insight is that the robot's path-count to each cell is built from two immediate predecessors. Once you recognize that structure, the brute force recursion collapses into DP, and the 1D version gives the cleanest interview solution.
