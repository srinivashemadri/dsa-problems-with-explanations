LeetCode 542 — 01 Matrix

Step 1 — Problem Statement

Input: A rectangular binary matrix mat containing only 0s and 1s. For every cell, we need the distance to the nearest 0, where distance is measured by the number of moves in the four cardinal directions: up, down, left, and right.

Output: A matrix of the same size where each cell contains the minimum number of steps required to reach any 0.

Key Constraints: The matrix can be large enough that any solution that re-scans the whole grid for every cell will be too slow. The values are only 0 or 1, which is a strong hint that we are dealing with shortest distance to a set of sources.

Edge Cases: a single cell matrix, an all-zero matrix, zeros appearing only on the border, zeros appearing in multiple places, and the standard LeetCode guarantee that there is at least one 0. If the matrix is already all zeros, the answer should be identical to the input. If there were no zero at all, the distance would be undefined, but that situation does not occur in the official problem.

Step 2 — Problem Understanding & Approach Overview

Strip away the story: this is really asking for the shortest distance from every grid cell to the nearest source node, where every 0-cell is a source and every move has equal cost 1.

The core challenge is to compute all these shortest paths efficiently without restarting the search from scratch for every single cell.

Category: graph shortest path on an unweighted grid, solved with multi-source BFS.

Mental model: do not think “for each 1, find the closest 0.” Think instead “all zeros expand outward at the same time, layer by layer, and the first time a cell is reached is its answer.”

Common trap: doing BFS or DFS separately from every 1-cell. That repeats the same work many times and turns a linear grid problem into a quadratic one. Another trap is trying to make a greedy local choice from neighbors in one pass, which misses the fact that the nearest zero may be far away.

Step 3 — Brute Force Solution

The naive idea is simple: for every cell, scan the entire matrix and compute its distance to each zero, then keep the minimum. 

for each cell (r, c):
    if mat[r][c] == 0:
        ans[r][c] = 0
    else:
        best = infinity
        for each cell (i, j) in the matrix:
            if mat[i][j] == 0:
                best = min(best, abs(r - i) + abs(c - j))
        ans[r][c] = best

Time Complexity: O((m × n)²). There are m × n cells, and for each cell we may scan all m × n cells again.

Space Complexity: O(m × n) for the answer matrix.

Performance bottleneck: every cell repeats a full-grid search. The same zero positions are re-evaluated again and again.

Step 4 — Intuition Building

Test Case 1

Input: 0

Observation: The cell is already a zero, so its nearest zero is itself.

Action: Assign distance 0 immediately.

Result: 0

Test Case 2

Input: 1 0 1

Observation: The middle cell is a source. The left and right cells are one step away from it. If you tried to solve each cell independently, you would redo the same work twice.

Action: Start from the zero and expand outward one layer at a time.

Result: 1 0 1

Test Case 3

Input:

0 0 0

0 1 0

1 1 1

Observation: There are multiple sources. The center 1 is surrounded by zeros, so its answer is 1. The bottom row cells are best reached from the closest zero above them, not from a single arbitrarily chosen zero.

Action: Let all zero cells enter the queue first, then process them in layers.

Result:

0 0 0

0 1 0

1 1 1

The key pattern is now visible: we are not searching from every cell outward. We are flooding the grid outward from all zeros simultaneously. Because each move costs the same, the first time a cell is reached is guaranteed to be the shortest distance.

A rare but important edge case is an all-zero matrix. In that case, the queue is initially full of every cell, but no updates are needed. The optimal method handles it naturally without special logic.

Signal to remember for future problems: when you see “distance to nearest source” on an unweighted grid, think multi-source BFS immediately.

Step 5 — Optimized Solution

The best-known practical solution here is multi-source BFS. Put every 0-cell into the queue first with distance 0. Then expand level by level into neighboring 1-cells. The first time a cell is assigned a distance, that distance is minimal because BFS explores in increasing number of moves.

C++17 Code:

vector<vector<int>> updateMatrix(vector<vector<int>>& mat) {
    int m = mat.size();
    if (m == 0) return {};
    int n = mat[0].size();

    vector<vector<int>> dist(m, vector<int>(n, -1));
    queue<pair<int, int>> q;

    for (int i = 0; i < m; ++i) {
        for (int j = 0; j < n; ++j) {
            if (mat[i][j] == 0) {
                dist[i][j] = 0;
                q.push({i, j});
            }
        }
    }

    int dr[4] = {1, -1, 0, 0};
    int dc[4] = {0, 0, 1, -1};

    while (!q.empty()) {
        auto [r, c] = q.front();
        q.pop();

        for (int k = 0; k < 4; ++k) {
            int nr = r + dr[k];
            int nc = c + dc[k];

            if (nr < 0 || nr >= m || nc < 0 || nc >= n) continue;
            if (dist[nr][nc] != -1) continue;

            dist[nr][nc] = dist[r][c] + 1;
            q.push({nr, nc});
        }
    }

    return dist;
}

Why this works: all zeros are treated as starting points at distance 0. BFS guarantees that when a cell is first reached, no shorter path can exist, because any shorter path would have had to be processed in an earlier BFS layer.

Why mark visited on enqueue, not on dequeue: the moment a cell gets its distance and enters the queue, its shortest distance is already fixed. If you wait until dequeue time, the same cell can be inserted multiple times from different neighbors.

Why a single BFS is enough: the queue starts with all zero cells, so the wavefronts from every source compete at the same time. That automatically chooses the nearest zero for each cell.

Dry Run

Input:

0 0 0

0 1 0

1 1 1

Initialization: all zero cells go into the queue with distance 0.

Queue contains the six 0-cells.

Pivot / Expansion Layer 0: pop each zero cell and try to update its neighbors.

The center cell (1,1) is first reached from a neighboring zero, so dist[1][1] = 1. The bottom-left cell (2,0) is first reached from (1,0), so dist[2][0] = 1. The bottom-middle cell (2,1) is first reached from (1,1) after it becomes 1, or from adjacent zeros through a shorter layer, giving the minimum possible value 1. The bottom-right cell (2,2) is similarly assigned 1.

Reverse check: none of these cells need to be revisited, because the first assignment already came from the nearest layer.

Final Result:

0 0 0

0 1 0

1 1 1

Extreme edge case handling: if the matrix is all zeros, every cell is inserted initially with distance 0, and the BFS loop performs no useful updates. That is exactly the correct answer and costs only linear time.

Time Complexity: O(m × n). Every cell is enqueued at most once, and each cell checks at most 4 neighbors. The total work is therefore linear in the number of cells.

Space Complexity: O(m × n). The distance matrix and queue can both grow to hold a constant fraction of the grid in the worst case.

Algorithm name: Multi-source BFS.
