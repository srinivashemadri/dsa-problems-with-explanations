Step 1 — Problem Statement

Input: A non-negative integer given as a string num, and an integer k telling how many digits must be removed.
Output: The smallest possible number, still represented as a string, after removing exactly k digits while keeping the remaining digits in the same relative order.
Key Constraints: The order of the remaining digits cannot change, leading zeros in the result must be removed, and if every digit is removed the answer must be "0".
Edge Cases: k = 0, k = n, numbers already in increasing order, numbers in decreasing order, repeated digits, and results that become empty or start with zeros after removals.

Step 2 — Problem Understanding & Approach Overview

Strip away the story: this is really about deleting exactly k characters from a string so that the remaining string is lexicographically and numerically smallest. The core challenge is deciding which digits should be removed so that the most significant positions become as small as possible. This is a classic monotonic stack problem. The mental model is simple: whenever a digit is larger than the digit after it, that larger digit is a bad choice for the final number because deleting it improves a more significant position. The most common mistake is trying to remove the globally largest digit instead of the first harmful “peak”; that greedy choice fails because position matters more than raw value.

Step 3 — Brute Force Solution

The naive idea is: repeat the following k times — scan from left to right, find the first index where num[i] > num[i + 1], remove num[i], and if no such index exists, remove the last digit. After all removals, strip leading zeros. 

Pseudocode

repeat k times:
    find first i such that num[i] > num[i + 1]
    if such i exists:
        delete num[i]
    else:
        delete last character

remove leading zeros
if string becomes empty:
    return "0"
else:
    return string

Time Complexity: O(k · n) in the usual analysis, and in practice often worse if each erase shifts characters inside a string. You scan many times and keep modifying the middle of the string.
Space Complexity: O(n) if you count the mutable string storage; otherwise O(1) auxiliary beyond the input representation.
Bottleneck: Repeated rescanning and repeated deletions from the middle.

The pattern becomes clear: the best digit to remove is usually the first digit that violates increasing order. That is exactly what a monotonic increasing stack detects in one pass. The signal that should immediately trigger this approach is: “delete k characters/digits to make the result smallest/largest while preserving order.”

Step 5 — Optimized Solution

This problem has one fully optimal solution: a monotonic increasing stack. We scan once, and while the current digit is smaller than the stack top and we still have deletions left, we pop from the stack. That removes a larger digit from a more significant position, which is always better than keeping it.

Why this works: If the current digit c is smaller than the previous digit top, then keeping top before c makes the number larger at an earlier position. Removing top improves the number more than removing some later digit. Because each digit is pushed once and popped once, the total work stays linear.

Pseudocode

use an empty stack of characters

for each digit c in num:
    while k > 0 and stack not empty and stack.top() > c:
        pop stack
        k--
    push c into stack

while k > 0:
    pop stack
    k--

remove leading zeros from stack
if nothing remains:
    return "0"
else:
    return the remaining digits as a string
string removeKdigits(string num, int k) {
    vector st;

    for (char c : num) {
        while (k > 0 && !st.empty() && st.back() > c) {
            st.pop_back();
            k--;
        }
        st.push_back(c);
    }

    while (k > 0 && !st.empty()) {
        st.pop_back();
        k--;
    }

    int i = 0;
    while (i < (int)st.size() && st[i] == '0') {
        i++;
    }

    if (i == (int)st.size()) return "0";
    return string(st.begin() + i, st.end());
}

Complexity

Time Complexity: O(n). Every digit is pushed once, and each digit can be popped at most once.
Space Complexity: O(n) for the stack that stores the digits of the candidate answer.

The subtle beginner trap here is to think “remove the largest digit” globally. That is wrong because the number’s value is dominated by the earliest positions. The correct greedy choice is local but position-aware: remove the first digit that makes the prefix worse.
