LeetCode 1011 — Ship Packages Within D Days

Following the requested LeetCode workflow. :contentReference[oaicite:0]{index=0}

Step 1 — Problem Statement

Input: You are given an array weights, where weights[i] is the weight of the i-th package, and an integer days.

Output: Return the minimum ship capacity needed so that all packages can be shipped in at most days days.

Key Constraints: Packages must be shipped in the given order. You cannot reorder them. On each day, the ship can carry a contiguous prefix of the remaining packages, as long as the total weight on that day does not exceed the chosen capacity.

Edge Cases:

• A single package.

• days = 1, which forces the capacity to be the sum of all weights.

• days = weights.size(), which forces the capacity to be at least the maximum single package weight.

• All weights identical.

• Very large total sum, where integer overflow must be avoided when computing the upper bound.

Step 2 — Problem Understanding & Approach Overview

Strip away the shipping story, and this is really asking: what is the smallest limit X such that the array can be partitioned into at most D contiguous groups, each with sum ≤ X?

The core challenge is not to construct one specific partition, but to find the minimum feasible capacity.

This is a binary search on answer problem. The mental model is: if a certain capacity works, then every larger capacity also works. That monotonic behavior is the key.

The subtle trap is trying to do dynamic programming or greedy partitioning without recognizing the monotonic feasibility check. Most candidates also forget that package order is fixed, so the valid shipment groups must be contiguous.

Step 3 — Brute Force Solution

The naive idea is to try every possible capacity from the largest single package up to the total sum, and for each capacity simulate how many days are needed.

function bruteForce(weights, days):
    low  = max(weights)
    high = sum(weights)

    for capacity from low to high:
        neededDays = 1
        currentLoad = 0

        for w in weights:
            if currentLoad + w > capacity:
                neededDays += 1
                currentLoad = 0
            currentLoad += w

        if neededDays <= days:
            return capacity

    return high

Why it works: For every candidate capacity, the inner loop greedily packs as many packages as possible into each day. That gives the minimum number of days required for that capacity.

Time Complexity: O(n * (sum - maxWeight + 1)). The outer loop can scan every capacity, and the inner loop scans the array once per capacity.

Space Complexity: O(1). Only a few variables are used.

Bottleneck: The range of possible capacities can be huge, so checking them one by one is far too slow.

Step 4 — Intuition Building

Test Case 1

Input: 1 2 3 1 1, days = 4

The packages must stay in order. A capacity that is too small will create extra days.

Action: Try capacity = 3

Day 1: 1 + 2 = 3

Day 2: 3

Day 3: 1 + 1 = 2

Result: 3 days are enough, so capacity 3 works.

Now notice the monotonic pattern: if 3 works, then 4, 5, 6... also work. That immediately suggests binary search.

Test Case 2

Input: 3 2 2 4 1 4, days = 3

Try a capacity that looks reasonable, say 6.

Action: Simulate greedily

Day 1: 3 + 2 = 5, next 2 would make 7, so stop

Day 2: 2 + 4 = 6, next 1 would make 7, so stop

Day 3: 1 + 4 = 5

Result: 6 works in 3 days.

If we test 5, the same greedy process creates more than 3 days. So the answer lies near this boundary. This is exactly the kind of “first feasible value” problem binary search is built for.

Test Case 3 (Edge Case)

Input: 10 50 100, days = 1

All packages must go in one day, so the ship must hold everything.

Action: Capacity must be 160

Result: The optimal answer is the total sum.

A naive method that tries to split into multiple days would be wrong here. The optimal approach handles this naturally because the feasibility check simply sees whether the entire array fits in one day.

Signal to recognize this approach in future problems: when the question asks for the minimum value that still satisfies a condition, and the condition becomes easier as the value increases, think binary search on answer.

Step 5 — Optimized Solution

Algorithm name: Binary Search on Answer + Greedy Feasibility Check

The key insight is that capacity feasibility is monotonic. If a ship capacity C can ship all packages within D days, then any capacity greater than C can also do it. That means we can binary search the smallest feasible capacity.

function canShip(weights, days, capacity):
    requiredDays = 1
    currentLoad = 0

    for w in weights:
        if currentLoad + w > capacity:
            requiredDays += 1
            currentLoad = 0
        currentLoad += w

    return requiredDays <= days

function shipWithinDays(weights, days):
    low = max(weights)
    high = sum(weights)

    while low < high:
        mid = low + (high - low) / 2

        if canShip(weights, days, mid):
            high = mid
        else:
            low = mid + 1

    return low
int shipWithinDays(vector<int>& weights, int days) {
    int low = 0;
    int high = 0;

    for (int w : weights) {
        low = max(low, w);
        high += w;
    }

    auto canShip = [&](int capacity) -> bool {
        int requiredDays = 1;
        int currentLoad = 0;

        for (int w : weights) {
            if (currentLoad + w > capacity) {
                requiredDays++;
                currentLoad = 0;
            }
            currentLoad += w;
        }

        return requiredDays <= days;
    };

    while (low < high) {
        int mid = low + (high - low) / 2;

        if (canShip(mid)) {
            high = mid;
        } else {
            low = mid + 1;
        }
    }

    return low;
}

Why the greedy check is correct: For a fixed capacity, taking as many packages as possible each day never hurts. Any earlier split would only increase or preserve the number of days, never reduce it.

Time Complexity: O(n log S), where S is the sum of all weights. The feasibility check is O(n), and binary search runs for O(log S) steps.

Space Complexity: O(1). The solution uses only a few counters and one lambda function.

Handled edge case: When days = 1, the feasibility check only succeeds when the capacity reaches the total sum. When days = weights.size(), the answer becomes the maximum element, because each package can be shipped on its own day.
