LeetCode 540 — Single Element in a Sorted Array

Step 1 — Problem Statement

Input: a sorted array in which every element appears exactly twice except one element that appears exactly once. The array is in non-decreasing order, and the total length is odd because all the paired elements contribute an even count plus one single element.

Output: return the single element that appears only once.

Key Constraints: the sorted order is the entire reason a logarithmic solution exists. Without sorting, this becomes a different problem. Also, every duplicated value appears in adjacent positions before the unique element, but the parity of indices shifts after the unique element.

Edge Cases: the array can have length 1; the single element can be at the beginning, in the middle, or at the end; the value range itself does not matter because the algorithm only compares neighbors; and the answer must still work when the single element is at an extreme boundary where one neighbor does not exist.

Step 2 — Problem Understanding & Approach Overview

This problem is really asking for the one index where the regular pair pattern breaks. Since the array is sorted, every duplicate normally occupies two adjacent positions. The moment the single element appears, the alignment of the remaining pairs changes.

The core challenge is to find that break point without scanning the entire array.

Category: binary search on structure / invariant-based search.

Mental model: before the unique element, pairs start at even indices; after the unique element, pairs start at odd indices. That parity shift is the invariant to exploit.

Subtle trap: many candidates do a normal binary search but forget that the “matching partner” of a middle index depends on parity. If you compare the wrong neighbor, the search direction becomes inconsistent and you can break the invariant.

Step 3 — Brute Force Solution

The simplest approach is to scan from left to right and check neighbors in pairs. Because duplicates are adjacent, the first pair that does not match reveals the single element. 

Pseudocode

for i from 0 to n - 1 step 2:
    if i == n - 1:
        return nums[i]
    if nums[i] != nums[i + 1]:
        return nums[i]

return -1

Each iteration checks one pair. If the array length is 1, the loop returns immediately. If the unique element is at the end, the loop reaches the last index and returns it.

Time Complexity: O(n). In the worst case, we may inspect about half the array, which is still linear.

Space Complexity: O(1). No extra data structure is needed.

Performance bottleneck: the scan still touches elements one by one. The sorted order is not being fully exploited.

Step 4 — Intuition Building
Test Case 1
Input: 1 1 2 3 3 4 4 8 8
Observation: pairs are intact at the start, then the single value 2 breaks the normal pairing alignment.
Action: check pairs from the left; the first mismatch is at 2 and 3.
Result: 2

This shows the main pattern: once the single element is passed, the indexing of pairs no longer matches the pre-single alignment.

Test Case 2
Input: 3 3 7 7 10 11 11
Observation: the first two pairs are fine. The break happens when 10 is compared with 11.
Action: keep moving by pairs until a mismatch appears.
Result: 10

This is the same structure, but the unique element is closer to the end. A linear scan still works, but it wastes the fact that the array is sorted.

Test Case 3 (Edge Case)
Input: 7 8 8 9 9
Observation: the single element is at the very beginning, so the pair pattern is shifted immediately.
Action: the first comparison 7 and 8 already fails.
Result: 7

This edge case matters because the optimal solution must not assume the single element is safely in the middle. A boundary answer should still be found without special-case code.

The signal to remember for future problems is this: when a sorted structure contains repeated pairs and exactly one “break” element, think about parity and use binary search on the invariant, not on the raw values alone.

Step 5 — Optimized Solution

There is one meaningful optimal solution here: a parity-aware binary search. The key insight is that before the single element, pairs begin at even indices; after the single element, that alignment flips. So we can use the midpoint to decide which half still follows the normal pairing pattern.

Optimized Idea

At any midpoint, force it to be even. Then compare nums[mid] with nums[mid + 1]. If they match, the unique element must be to the right. If they do not match, the unique element is at mid or to the left. 

Pseudocode

left = 0
right = n - 1

while left < right:
    mid = left + (right - left) / 2
    if mid is odd:
        mid = mid - 1

    if nums[mid] == nums[mid + 1]:
        left = mid + 2
    else:
        right = mid

return nums[left]
Why This Works

For indices before the single element, the first element of each pair sits at an even index. After the single element, that rule is broken. By forcing the midpoint to the left element of a pair candidate, we can test whether the left side still has a perfect pairing structure.

If nums[mid] equals nums[mid + 1], then all elements up to mid + 1 are consistent with the normal pairing pattern, so the unique element must lie to the right. Otherwise, the break happens at mid or to the left.

Full Working C++ Code
int singleNonDuplicate(vector<int>& nums) {
    int left = 0;
    int right = (int)nums.size() - 1;

    while (left < right) {
        int mid = left + (right - left) / 2;

        if (mid % 2 == 1) {
            mid--;
        }

        if (nums[mid] == nums[mid + 1]) {
            left = mid + 2;
        } else {
            right = mid;
        }
    }

    return nums[left];
}
Dry Run

Input: 1 1 2 3 3 4 4 8 8

Step 1 — Initial range: left = 0, right = 8
Mid: 4 (already even)
Check: nums[4] = 3, nums[5] = 4
Action: mismatch, so the single element is at mid or to the left
New range: left = 0, right = 4

Step 2 — New range: left = 0, right = 4
Mid: 2 (already even)
Check: nums[2] = 2, nums[3] = 3
Action: mismatch again, so shrink to the left half
New range: left = 0, right = 2

Step 3 — New range: left = 0, right = 2
Mid: 1, adjusted to 0 because we force even index
Check: nums[0] = 1, nums[1] = 1
Action: match, so the single element is to the right
New range: left = 2, right = 2

Final Result: nums[2] = 2

Extreme Edge Case Handling

For a length-1 array such as [5], the loop never runs because left == right from the beginning. The function directly returns 5. For a single element at the very beginning, such as [7,8,8,9,9], the first comparison fails and the search immediately moves left. For a single element at the very end, such as [1,1,2,2,3], the comparisons keep matching and the range shrinks toward the last index.

Time Complexity: O(log n). Each iteration cuts the search space roughly in half.

Space Complexity: O(1). Only a constant number of variables are used.

Algorithm name: parity-aware binary search on sorted pairs.
