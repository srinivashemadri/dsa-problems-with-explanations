LeetCode 79 — Word Search
Step 1 — Problem Statement

Input: A 2D character grid board and a string word. You may start from any cell and move one step at a time in four directions: up, down, left, right.

Output: Return true if the word can be formed by a path in the grid, where each character of the word matches the current cell, and each cell can be used at most once in that path. Otherwise return false.

Key Constraints: The same cell cannot be reused in a single path. Moves are only 4-directional. The word length can be larger than the number of cells, which immediately makes the answer impossible.

Edge Cases: Empty board, empty word, single-cell board, word longer than total cells, repeated letters in the board, repeated letters in the word, paths that almost work but fail at the last character, and boards where many cells contain the same starting letter.

Step 2 — Problem Understanding & Approach Overview

This is really a path-existence problem on a grid with a strict no-reuse rule. Strip away the story: you are asked whether a string exists as a simple path in a graph formed by the grid cells.

Core challenge: Explore many possible paths without revisiting a cell and without blowing up time unnecessarily.

Category: Backtracking / DFS on grid.

Mental model: Think of each cell as a potential starting point. From there, try to match the word one character at a time while marking cells as temporarily blocked, then undo the mark when you return.

Common trap: Candidates often forget to unmark cells during backtracking, or they mark too late and accidentally allow reuse in the same path. Another subtle mistake is starting DFS from only one occurrence of the first character instead of every possible occurrence.

Step 3 — Brute Force Solution

Naively, from every cell, try every possible path of length word.length() by recursively moving in four directions, while checking that cells are not reused.

Pseudocode:

for each cell (r, c) in board:
    if board[r][c] matches word[0]:
        if DFS(r, c, 0) returns true:
            return true
return false

DFS(r, c, index):
    if index == word.length:
        return true
    if out of bounds or board[r][c] != word[index] or already visited:
        return false

    mark board[r][c] as visited
    try all 4 directions:
        if DFS(next_r, next_c, index + 1) returns true:
            return true
    unmark board[r][c]
    return false

Time Complexity: O(m × n × 4L) in the worst case, where m × n is the grid size and L is the word length. From each starting cell, each step branches into up to 4 directions.

Space Complexity: O(L) recursion depth in the DFS stack, ignoring the board marking.

Bottleneck: Exponential branching. The search tree explodes when the board has many repeated letters and many paths appear valid for the first few characters.

    The next needed letters are B -> C -> C -> E -> D.

What this shows: One valid path is enough. The search must be allowed to turn corners; it is not a straight-line match.

    There are multiple 'S' cells.
    The top-left 'S' does not work for the full word.

What this shows: You must try every possible starting position, not just the first matching cell. A later start can succeed even if an earlier one fails.

Test Case 3 (Edge Case)

Input:
board =
A A
A A
word = AAAAA

    Total cells = 4, but word length = 5.
    It is impossible to use 5 distinct cells.
Action:
    No search can succeed, because one cell cannot be reused.
Result:
    false

What this shows: A quick length check can eliminate impossible cases early. If word.length() > m × n, return false immediately.

Key insight: The problem becomes manageable once each recursive path owns its own temporary visited state. That lets us test one path fully, then restore the board and try another path cleanly.

Signal to remember: When you see “use each cell at most once” plus “find a path that spells something,” think DFS + backtracking immediately.

Step 5 — Optimized Solution

There is one meaningful optimal solution here: DFS with backtracking and pruning. This is the standard fully optimal approach for interview purposes.

C++17 Code

bool exist(vector<vector<char>>& board, string word) {
    int m = board.size();
    int n = board[0].size();
    if (word.size() > m * n) return false;

    function<bool(int,int,int)> dfs = [&](int r, int c, int idx) -> bool {
        if (idx == (int)word.size()) return true;
        if (r < 0 || r >= m || c < 0 || c >= n) return false;
        if (board[r][c] != word[idx]) return false;

        char saved = board[r][c];
        board[r][c] = '#';  // mark visited

        bool found =
            dfs(r + 1, c, idx + 1) ||
            dfs(r - 1, c, idx + 1) ||
            dfs(r, c + 1, idx + 1) ||
            dfs(r, c - 1, idx + 1);

        board[r][c] = saved;  // restore
        return found;
    };

    for (int i = 0; i < m; ++i) {
        for (int j = 0; j < n; ++j) {
            if (board[i][j] == word[0] && dfs(i, j, 0)) {
                return true;
            }
        }
    }
    return false;
}

Why this works: Each recursive call represents one partial path. Marking the current cell prevents reuse in the same path. Restoring it after exploring all children ensures other paths remain unaffected.

Why the length check matters: If the word is longer than all cells combined, no path can exist. This is a simple but effective pruning rule.

Dry Run

Test Case:
board =
A B C E
S F C S
A D E E
word = ABCCED

Pivot:
    Start at (0,0) = A

Step 1:
    Match A with word[0]
    Mark (0,0) visited

Step 2:
    Need B
    Try neighbors of (0,0)
    Right (0,1) = B matches

Step 3:
    Need C
    From (0,1), try neighbors
    Right (0,2) = C matches

Step 4:
    Need C
    From (0,2), try neighbors
    Down (1,2) = C matches

Step 5:
    Need E
    From (1,2), try neighbors
    Down (2,2) = E matches

Step 6:
    Need D
    From (2,2), try neighbors
    Left (2,1) = D matches

Final Result:
    All characters matched in order
    Return true

How the edge case is handled: In the 2x2 board with word length 5, the length check fails before any DFS begins. That avoids wasted search.

Time Complexity: O(m × n × 4L) in the worst case, where L is the word length. The first character can start from up to m × n cells, and each subsequent step can branch into up to 4 directions. In practice, the visited restriction reduces some branching, but the worst-case upper bound remains exponential.

Space Complexity: O(L) due to recursion depth. The algorithm uses the board itself for marking, so no extra visited matrix is needed.

Algorithm Name: Depth-First Search with Backtracking.

Why a beginner often doubts this code: The restore step feels risky at first. The key is that restore happens only after exploring all paths from the current cell. That means the cell is blocked only for the current path, which is exactly what “cannot reuse a cell” means.
