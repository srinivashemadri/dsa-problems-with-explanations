LeetCode 503 — Next Greater Element II
Step 1 — Problem Statement

Input: You are given a circular array of integers. “Circular” means that after the last element, the array continues again from the first element.

Output: For every index, return the first element to its right, moving circularly, that is strictly greater than the current element. If no such element exists, return -1 for that position.

Key Constraints: The array can contain duplicates, so “strictly greater” matters. The circular nature is the real twist: the next greater element may lie before the current index in the original array. The answer must be computed efficiently because a naive restart-from-beginning approach can repeat work too much.

Edge Cases: An array with one element, an array where all values are identical, an array already strictly increasing, an array strictly decreasing, and cases where the next greater element appears only after wrap-around are all important. Duplicates are especially tricky because equal values must not be treated as greater.

Step 2 — Problem Understanding & Approach Overview

Strip away the story, and this is really asking: for each position, how far to the right do I need to look in a circular order before I find a strictly larger value?

The core challenge is avoiding repeated scanning of the same suffix for every index. This is a classic monotonic stack problem, and the circular behavior is handled by simulating two passes over the array.

The mental model is simple: imagine scanning from right to left while maintaining a stack of “useful candidates” that are in strictly decreasing order from top to bottom. The top of the stack is always the nearest valid greater candidate for the current element.

The subtle trap is forgetting that the array wraps around. A lot of candidates do one linear pass and miss answers that appear only after the end of the array. Another common mistake is using a stack but not popping all values that are less than or equal to the current number, which breaks the “next greater” guarantee.

Step 3 — Brute Force Solution

For every index, scan forward one step at a time, wrapping around with modulo, until you either find a greater element or come back to the same index.

for each i from 0 to n - 1:
    answer[i] = -1
    for step from 1 to n - 1:
        j = (i + step) % n
        if nums[j] > nums[i]:
            answer[i] = nums[j]
            break

Time Complexity: O(n^2). For each of the n positions, we may scan almost the full array in the worst case.

Space Complexity: O(1) extra space, ignoring the output array.

Performance Bottleneck: The same elements get rechecked again and again for different indices. That repeated work is exactly what the optimized stack removes.

Step 4 — Intuition Building

Test Case 1

Input: 1 2 1
    The next greater for 1 at index 0 is 2
    The next greater for 2 does not exist
    The next greater for 1 at index 2 wraps around to 2

Action: If we scan from right to left, we can keep only the candidates that are still useful.

Result: 2 -1 2

Test Case 2

Input: 3 2 1
    Every element is larger than everything to its right in the original order
    But because the array is circular, 1 can see 3, and 2 can also see 3

Action: A one-pass solution fails here. We need a second virtual pass so each index can “see” the beginning of the array.

Result: -1 3 3

Test Case 3 (Edge Case)

Input: 2 2 2
    All elements are equal
    Equal is not greater, so no element can ever find a next greater value

Action: While maintaining the stack, every equal value gets removed because it cannot help the current index.

Result: -1 -1 -1

The key insight is that once a value is smaller than or equal to the current value, it can never be the next greater element for this current index or for any earlier index that sees this current value first. That is why the stack stays monotonic. For the circular part, scanning the array twice lets the left side of the original array act like a continuation of the right side.

What should instantly make you think of this approach in a future problem is this combination: “next greater/smaller,” “nearest valid candidate,” and “wrap-around” or “circular” behavior.

Step 5 — Optimized Solution

Algorithm: Monotonic Decreasing Stack with Two-Pass Circular Simulation.

We iterate from 2n - 1 down to 0. The index we actually inspect is i % n. This simulates seeing the array twice from right to left. The stack stores candidate values in decreasing order. For each current value, we remove everything that is less than or equal to it, because those values cannot be the next greater element. After cleanup, the top of the stack is the first greater value to the right in circular order, but we only record answers during the first virtual pass (i < n).

Why two passes and why not one? In a circular array, an element near the front may need to look beyond the end and wrap to the beginning. One pass from right to left only sees the suffix; the second pass makes the prefix available as if it were appended to the end.

Why use i % n? Because we want to repeatedly access the same physical array positions while conceptually walking through a doubled version of the array. The modulo converts the virtual index back to a real index.

Why store values and not necessarily indices? For this problem, the answer is the value of the next greater element, not its position. Values are enough because the only operation we need is comparison. Storing indices is also valid, but not required here.

Why pop while <= and not just <? Because the problem asks for a strictly greater element. Equal values do not qualify, so they must be removed as well.

Full working C++17 code:

vector<int> nextGreaterElements(vector<int>& nums) {
    int n = (int)nums.size();
    vector<int> ans(n, -1);
    stack<int> st;

    for (int i = 2 * n - 1; i >= 0; --i) {
        int cur = nums[i % n];

        while (!st.empty() && st.top() <= cur) {
            st.pop();
        }

        if (i < n) {
            ans[i] = st.empty() ? -1 : st.top();
        }

        st.push(cur);
    }

    return ans;
}

Virtual scan from right to left:
i = 5, cur = 1     Stack before: empty
    Action: push 1
    Stack after: [1]

i = 4, cur = 2     Stack before: [1]
    Pop 1 because 1 <= 2
    Action: push 2
    Stack after: [2]

i = 3, cur = 1     Stack before: [2]
    Top = 2, so 2 is the next greater for this 1 in the virtual world
    Action: push 1
    Stack after: [2, 1]

i = 2, cur = 1     Stack before: [2, 1]
    Pop 1 because equal is not greater
    Top = 2
    Action: push 1
    Stack after: [2, 1]

i = 1, cur = 2     Stack before: [2, 1]
    Pop 1, then pop 2 because both are <= 2
    No greater element remains
    Answer[1] = -1
    Action: push 2
    Stack after: [2]

i = 0, cur = 1     Stack before: [2]
    Top = 2
    Answer[0] = 2
    Action: push 1
    Stack after: [2, 1]

Final Result: 2 -1 2

How this handles the extreme edge case: For input like 5 4 3 2 1, the stack still works because the second virtual pass exposes the earlier larger values to the later elements. For input like 2 2 2, every equal value gets popped, so no false “greater” answer is ever produced.

Time Complexity: O(n). Each element is pushed at most twice across the two virtual passes and popped at most twice overall, so the total stack work stays linear.

Space Complexity: O(n) for the stack in the worst case, plus the output array.

The most important pattern to remember is this: whenever a problem asks for the nearest next greater or smaller item, especially in a circular setting, think monotonic stack first.
