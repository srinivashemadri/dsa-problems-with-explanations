LeetCode 493 — Reverse Pairs

Step 1 — Problem Statement
Input: An integer array nums.
Output: The number of reverse pairs, where a reverse pair is an index pair (i, j) such that i < j and nums[i] > 2 * nums[j].
Key Constraints: The array can contain negative numbers, duplicates, and values large enough that 2 * nums[j] can overflow a 32-bit int if handled carelessly. The ordering condition i < j matters, so this is not just about comparing all unordered pairs.
Edge Cases: empty array, single element array, all elements identical, already increasing order, already decreasing order, negative values, and values near integer limits where multiplication must be done in 64-bit.
Step 2 — Problem Understanding & Approach Overview
Stripped of the story, this asks for the number of index pairs whose left value is strictly more than twice the right value. The core challenge is counting such pairs efficiently without checking every pair one by one.

Category: Array + Divide and Conquer / Merge Sort Counting.

Mental model: Think of the array as something we can sort while simultaneously counting how many cross-boundary pairs satisfy the inequality. The key is that once both halves are sorted, the condition can be counted with two pointers instead of nested loops.

Common trap: Many candidates either do brute force O(n^2) or try to count during merge without preserving the sorted structure needed for linear counting. Another frequent mistake is integer overflow when computing 2 * nums[j].
Step 3 — Brute Force Solution
for i from 0 to n - 1:
    for j from i + 1 to n - 1:
        if nums[i] > 2 * nums[j]:
            count++
return count
This checks every valid pair (i, j), so the time complexity is O(n^2). The nested loop is the bottleneck because each element may be compared with every later element. The space complexity is O(1), ignoring input storage.

Step 5 — Optimized Solution
There is one standard fully optimal approach here: merge sort counting. The array is recursively split into two sorted halves, reverse pairs inside each half are counted recursively, and cross pairs are counted before merging.
Idea: If left half and right half are already sorted, then for each element in the left half, we can move a pointer through the right half until nums[i] > 2 * nums[j] stops being true. Because both halves are sorted, this pointer never moves backward, so counting becomes linear for each merge level.
Pseudocode: 
function sortAndCount(l, r):
    if l >= r:
        return 0

    mid = (l + r) / 2
    count = sortAndCount(l, mid)
    count += sortAndCount(mid + 1, r)

    j = mid + 1
    for i from l to mid:
        while j <= r and nums[i] > 2LL * nums[j]:
            j++
        count += (j - (mid + 1))

    merge nums[l..mid] and nums[mid+1..r]
    return count
Full working C++17 code: 
long long mergeSortCount(vector& nums, vector& temp, int l, int r) {
    if (l >= r) return 0;

    int mid = l + (r - l) / 2;
    long long count = 0;

    count += mergeSortCount(nums, temp, l, mid);
    count += mergeSortCount(nums, temp, mid + 1, r);

    int j = mid + 1;
    for (int i = l; i <= mid; ++i) {
        while (j <= r && (long long)nums[i] > 2LL * (long long)nums[j]) {
            ++j;
        }
        count += (j - (mid + 1));
    }

    int i = l;
    j = mid + 1;
    int k = l;

    while (i <= mid && j <= r) {
        if (nums[i] <= nums[j]) {
            temp[k++] = nums[i++];
        } else {
            temp[k++] = nums[j++];
        }
    }

    while (i <= mid) temp[k++] = nums[i++];
    while (j <= r) temp[k++] = nums[j++];

    for (int idx = l; idx <= r; ++idx) {
        nums[idx] = temp[idx];
    }

    return count;
}

int reversePairs(vector& nums) {
    if (nums.empty()) return 0;
    vector temp(nums.size());
    return (int)mergeSortCount(nums, temp, 0, (int)nums.size() - 1);
}

Extreme edge case handling:
Input: -5 -5 -5
Since -5 > 2 * -5 becomes -5 > -10, every earlier index forms a reverse pair with every later one. The merge-sort approach still counts this correctly because the inequality works for negatives too. The cast to 2LL prevents overflow on large values.
Time Complexity: O(n log n). Each level of recursion does linear counting plus linear merging, and there are log n levels.
Space Complexity: O(n) for the temporary merge array, plus O(log n) recursion stack.
Algorithm name: Merge Sort Counting / Divide and Conquer Counting.
