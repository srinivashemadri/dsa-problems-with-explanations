Step 1 — Problem Statement

Input: A square matrix matrix of size n x n, where each cell contains an integer. The matrix must be rotated 90 degrees clockwise.

Output: The same matrix after rotation, modified in place. No extra 2D matrix should be used for the final answer.

Key Constraints: The matrix is square, so every row has the same length as the number of rows. The important follow-up is in-place rotation, which forces us to think about index transformations instead of building a fresh answer matrix.

Edge Cases:
- n = 1: a 1 x 1 matrix stays unchanged.
- n = 2: the smallest non-trivial rotation, useful for checking index logic.
- All values identical: the structure still matters even if the visual result looks unchanged.
- Already “symmetric-looking” matrices can still change after rotation, so do not confuse transpose with rotation.

Step 2 — Problem Understanding & Approach Overview

This problem is really asking you to remap every element from position (i, j) to its rotated position (j, n - 1 - i). The story is just a matrix rotation; the core challenge is to do it without allocating a second matrix.

The category is matrix manipulation / in-place transformation.

The mental model is simple: a clockwise rotation can be decomposed into two easier moves — first swap rows with columns through a transpose, then reverse every row. That composition produces the exact 90-degree clockwise effect.

The subtle trap is to try to move elements one by one in a cycle without fully reasoning about four-way placements, which often causes overwrites or off-by-one mistakes. Another common mistake is doing only transpose and forgetting the row reversal.

Step 3 — Brute Force Solution

The most naive idea is to create a new n x n matrix, place each value directly into its rotated location, and then copy it back if needed. 

for i from 0 to n - 1:
    for j from 0 to n - 1:
        newMatrix[j][n - 1 - i] = matrix[i][j]

copy newMatrix back into matrix

Each element is visited once, so the time complexity is O(n^2). The extra matrix also takes O(n^2) space. The bottleneck is the additional 2D storage, which violates the in-place requirement.

The inefficiency in the brute-force thinking is that direct relocation forces you to manage overwritten values. The cleaner structure is to exploit a decomposition: transpose turns rows into columns, and reversing each row completes the clockwise turn.

The signal that should immediately trigger this same approach is: “rotate a square matrix in place”. That phrasing almost always means “transpose + reverse” or an equivalent layered swap strategy.

Step 5 — Optimized Solution

There is one fully optimal in-place approach here: transpose the matrix, then reverse every row. This is the standard interview-grade solution and it avoids extra 2D memory.

Why it works: Transpose converts matrix[i][j] into matrix[j][i], which flips the matrix across its main diagonal. After that, reversing each row shifts the elements into their final clockwise-rotated positions.

Optimized Solution
void rotate(vector<vector<int>>& matrix) {
    int n = matrix.size();

    // Step 1: Transpose the matrix
    for (int i = 0; i < n; ++i) {
        for (int j = i + 1; j < n; ++j) {
            swap(matrix[i][j], matrix[j][i]);
        }
    }

    // Step 2: Reverse every row
    for (int i = 0; i < n; ++i) {
        reverse(matrix[i].begin(), matrix[i].end());
    }
}

Edge case check: For n = 1, the transpose loop does nothing and reversing the single row also changes nothing. So the algorithm naturally handles the smallest case without special branches.

Time Complexity: O(n^2). The transpose visits only the upper triangle above the diagonal, which is still proportional to the number of cells. The row reversals together also touch every element once. Combined cost remains quadratic.

Space Complexity: O(1). All swaps are done in place, and no extra matrix or auxiliary array is used.
