LeetCode 875 — Koko Eating Bananas

Step 1 — Problem Statement

Input: An array piles where piles[i] is the number of bananas in the i-th pile, and an integer h representing the total number of hours Koko has to finish all bananas.

Output: The minimum integer eating speed k such that Koko can eat all bananas within h hours. In one hour, she can eat up to k bananas from a single pile; if the pile has fewer than k, she finishes that pile and stops for that hour.

Key Constraints: The answer is an integer speed, and the total hours needed at a given speed is monotonic: if Koko can finish at speed k, then any larger speed also works. This monotonic property is the core reason binary search applies.

Edge Cases: A single pile, all piles equal, very large piles, h equal to the number of piles, h much larger than needed, and the extreme case where the minimum speed is exactly the maximum pile size. Another subtle case is when rounding up matters, because each pile may take a partial hour.

Step 2 — Problem Understanding & Approach Overview

This problem is really asking: what is the smallest integer speed that makes a feasibility condition true? The story is just packaging; the core task is to search for the minimum value in a monotonic boolean space.

The algorithmic challenge is to compute, for a candidate speed, how many hours are required, and then use that result to guide the search.

Category: Binary Search on Answer.

Mental Model: Imagine a dial for eating speed. At low speeds, Koko fails. At high speeds, Koko succeeds. Somewhere there is a boundary between failure and success, and we need the first successful speed.

Subtle Trap: The most common mistake is trying to simulate hour by hour instead of counting hours per pile using ceiling division. The other trap is getting the boundary logic wrong in binary search and returning the wrong side of the transition.

Step 3 — Brute Force Solution

Try every possible speed from 1 to max(piles). For each speed, compute the total hours needed by summing ceil(pile / speed) over all piles. Return the first speed that fits within h. 

for speed from 1 to maxPile:
    hours = 0
    for each pile in piles:
        hours += ceil(pile / speed)
    if hours <= h:
        return speed

Time Complexity: O(maxPile × n), where n is the number of piles. We test every possible speed and scan all piles for each speed.

Space Complexity: O(1), ignoring input storage.

Performance Bottleneck: The speed range can be huge, so checking every speed is too slow.

Step 4 — Intuition Building
Test Case 1

Input: piles = [3, 6, 7, 11], h = 8
    Try speed 4
    Hours per pile: ceil(3/4)=1, ceil(6/4)=2, ceil(7/4)=2, ceil(11/4)=3
Action: Total hours = 1 + 2 + 2 + 3 = 8
Result: Speed 4 works.

Now try speed 3
    Hours per pile: 1, 2, 3, 4
Action: Total hours = 10
Result: Speed 3 fails.

This shows the boundary clearly: smaller speeds fail, larger speeds may work. That is exactly the shape binary search needs.

Test Case 2

Input: piles = [30, 11, 23, 4, 20], h = 5
    Here Koko has only as many hours as piles.
    That means she must finish exactly one pile per hour, so the speed must be at least the largest pile.

Action: Minimum feasible speed = 30
Result: Answer is 30.

This is an extreme case that defeats naive intuition. Even though the total bananas are not enormous, the hour limit forces the speed to jump to the maximum pile size.

Test Case 3 (Edge Case)

Input: piles = [312884470], h = 968709470
    One pile only, and plenty of hours.
    Even speed 1 is enough because ceil(312884470 / 1) = 312884470, which is within the hour limit.

Action: Minimum feasible speed = 1
Result: Answer is 1.

This shows why the lower bound can be as small as 1. It also reinforces the key pattern: we are not searching for a pile-related index, but for the smallest valid integer speed.

Signal to recognize this approach in future problems: whenever a numeric answer becomes feasible/infeasible in a monotonic way, search the answer space with binary search.

Step 5 — Optimized Solution

There is only one meaningful optimized solution here: binary search on the answer. There is no separate intermediate optimization worth splitting out.

We define a helper that checks whether a given speed is enough. Then we binary search the smallest speed that passes the check.

Idea: If speed k works, then every speed greater than k also works. So the valid speeds form a suffix, and we need the leftmost valid one.

Pseudocode: 

function canFinish(speed):
    hours = 0
    for each pile in piles:
        hours += ceil(pile / speed)
    return hours <= h

low = 1
high = max(piles)

while low < high:
    mid = low + (high - low) / 2
    if canFinish(mid):
        high = mid
    else:
        low = mid + 1

return low

Why this works: The check function is monotonic. Binary search on a monotonic predicate finds the first true value, which is exactly the minimum feasible speed.

Time Complexity: O(n log M), where n is the number of piles and M = max(piles). Each feasibility check scans all piles in O(n), and binary search performs O(log M) checks.

Space Complexity: O(1), excluding input storage.

Dry Run

Input: piles = [3, 6, 7, 11], h = 8

Initial Range: low = 1, high = 11

Step 1: mid = 6
    Hours = ceil(3/6)=1 + ceil(6/6)=1 + ceil(7/6)=2 + ceil(11/6)=2 = 6
Action: 6 works, so move left: high = 6

Step 2: low = 1, high = 6, mid = 3
    Hours = 1 + 2 + 3 + 4 = 10
Action: 3 fails, so move right: low = 4

Step 3: low = 4, high = 6, mid = 5
    Hours = 1 + 2 + 2 + 3 = 8
Action: 5 works, so move left: high = 5

Step 4: low = 4, high = 5, mid = 4
    Hours = 1 + 2 + 2 + 3 = 8
Action: 4 works, so move left: high = 4

Final: low = high = 4
Result: 4

Extreme Edge Case Handling: If h = piles.size(), then each pile must be cleared in one hour, so the algorithm naturally pushes the answer toward max(piles). If h is large enough, the search naturally collapses to 1. No special-case branching is required.

Interview-ready C++17 code: 

int minEatingSpeed(vector& piles, int h) {
    int low = 1;
    int high = *max_element(piles.begin(), piles.end());

    while (low < high) {
        int mid = low + (high - low) / 2;
        long long hours = 0;

        for (int pile : piles) {
            hours += (pile + mid - 1) / mid;
        }

        if (hours <= h) {
            high = mid;
        } else {
            low = mid + 1;
        }
    }

    return low;
}
