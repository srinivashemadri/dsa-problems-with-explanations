Step 1 — Problem Statement

Input: An integer n, which represents an n × n chessboard. You need to place n queens on the board so that no two queens attack each other.

Output: Return all distinct valid boards. Each board is represented as n strings of length n, where 'Q' means a queen and '.' means an empty cell.

Key Constraints: The important constraint is not the board size itself, but the attack rules. A queen attacks along the same row, same column, and both diagonals. Since we place exactly one queen per row, the real search space is “which column should the queen go in for each row?”

Edge Cases:
• n = 1: one queen fits trivially.
• n = 2 or 3: no solution exists.
• Larger n: multiple solutions, and the same partial placement can lead to a dead end many levels later.
• The board is empty at the start, so the first few placements must be handled carefully without assuming a valid continuation.

Step 2 — Problem Understanding & Approach Overview

This problem is really asking for all valid permutations of queen placements under pairwise conflict rules. The story is just a wrapper; algorithmically, it is a backtracking / DFS / constraint satisfaction problem.

The core challenge is that every choice affects future choices through column and diagonal constraints. So you must explore one row at a time, reject invalid columns immediately, and backtrack the moment a partial placement becomes impossible.

Mental model: Think of the board as a decision tree where each level is one row. At each level, you try every column that is still safe.

Subtle trap: Many candidates either scan the whole board again and again for every placement, or they forget that diagonals are as important as columns. The real unlock is: once you place one queen per row, you only need to track three forbidden sets — used columns, main diagonals, and anti-diagonals.

Step 3 — Brute Force Solution

The naive idea is: generate every possible placement of queens row by row, and after each full arrangement, check whether any two queens attack each other. 

Brute Force Pseudocode

generate all ways to place one queen in each row:
    for row = 0 to n-1:
        try every column from 0 to n-1

for each complete arrangement:
    check every pair of queens
    if no attack exists:
        store the board

Time Complexity: O(nn · n) in spirit, or O(nn+1) if you count the validation scan. There are n choices for each of n rows, so the search space is huge. The bottleneck is that most of these states are doomed, but brute force still explores them and only rejects them late.

Space Complexity: O(n2) for the board plus O(n) recursion depth, ignoring output storage.

Step 4 — Intuition Building

Test Case 1 — n = 1

Input: 1

    Only one cell exists.
    One queen can be placed safely.

Action: Place Q at (0,0)

Result:
Q

Test Case 2 — n = 2 or n = 3 (No Solution)

Input: 2

    Row 0: try col 0
    Row 1: no safe column remains

    Row 0: try col 1
    Row 1: no safe column remains

Action: Backtrack all the way

Result: no valid board

This is important because it proves that the algorithm must support “explore and fail” cleanly. A greedy placement will not work.

Test Case 3 — n = 4

Input: 4

    Start with row 0.
    Try col 0 first.

Row 0: Q . . .
    Safe columns for row 1 are limited by:
    - used column 0
    - diagonals from (0,0)

Row 1: try col 2
    Row 2 now has no safe column
    This branch dies early

Action: Backtrack row 1, then row 0

Now try row 0: . Q . .
    This choice opens a valid chain later

One valid path:
Row 0 -> col 1
Row 1 -> col 3
Row 2 -> col 0
Row 3 -> col 2

Result:
. Q . .
. . . Q
Q . . .
. . Q .

The key insight is visible here: you never need to re-check the whole board from scratch. You only need to know whether a column or diagonal is already occupied. That means the future problem pattern to recognize is: “place one item per level, and each placement is blocked by a small set of reusable constraints.”

Step 5 — Optimized Solution 1 (Intermediate)

The first meaningful optimization is to keep three boolean trackers: one for used columns, one for main diagonals, and one for anti-diagonals. Then each safety check becomes O(1). 

Optimized Solution 1 Pseudocode

dfs(row):
    if row == n:
        save the board
        return

    for col from 0 to n-1:
        if column col is free
           and main diagonal (row - col) is free
           and anti-diagonal (row + col) is free:

            place queen
            mark column and diagonals
            dfs(row + 1)
            unplace queen
            unmark column and diagonals

What was eliminated compared to brute force: repeated board-wide conflict scanning. Each candidate placement is now rejected immediately if it violates a known constraint.

Time Complexity: Worst-case still exponential, but much better in practice. The search tree is pruned aggressively, and each check is O(1). A common way to describe it is O(n!) style branching, with O(1) safety checks and O(n2) per completed board to materialize the strings.

Space Complexity: O(n) recursion depth plus O(n) for the constraint trackers, excluding output storage.

Step 5 — Optimized Solution 2 (Best Known / Fully Optimal)

The next refinement is to encode the same three constraint sets using bitmasks. This does not change the asymptotic search complexity, but it makes the checks faster and the implementation very clean.

Why bitmasks work: If a bit is set in cols, that column is occupied. For diagonals, when you move from one row to the next:
• one diagonal threat shifts left,
• the other diagonal threat shifts right.
So the forbidden masks naturally “move” with the next row. 

Optimized Solution 2 Pseudocode

dfs(row, colsMask, diag1Mask, diag2Mask):
    if row == n:
        save board
        return

    available = fullMask & ~(colsMask | diag1Mask | diag2Mask)

    while available is not zero:
        pick lowest set bit as a candidate column
        remove that bit from available
        place queen in that column
        recurse to next row with updated masks
        remove queen
  
vector<vector<string>> solveNQueens(int n) {
    vector<vector<string>> ans;
    vector<string> board(n, string(n, '.'));
    int fullMask = (1 << n) - 1;

    auto dfs = [&](auto&& self, int row, int cols, int d1, int d2) -> void {
        if (row == n) {
            ans.push_back(board);
            return;
        }

        int available = fullMask & ~(cols | d1 | d2);

        while (available) {
            int bit = available & -available;   // lowest set bit
            available -= bit;

            int col = 0;
            int temp = bit;
            while ((temp >> 1) != 0) {
                temp >>= 1;
                ++col;
            }

            board[row][col] = 'Q';
            self(self, row + 1, cols | bit, (d1 | bit) << 1, (d2 | bit) >> 1);
            board[row][col] = '.';
        }
    };

    dfs(dfs, 0, 0, 0, 0);
    return ans;
}

Dry run on n = 4: the algorithm starts with all columns available in row 0. It tries one column, immediately updates the forbidden masks, and moves to row 1. When a later row has no available bit left, the function returns and the previous row tries the next bit. That is exactly the same logical backtracking as the set-based solution, just encoded more compactly.

Edge case handling:
• For n = 1, fullMask = 1, the only cell is chosen and the answer is a single board.
• For n = 2 or 3, every branch dies before reaching row n, so the returned list stays empty.

Time Complexity: Same search-space behavior as optimized backtracking, with O(1) constraint checks per candidate. The dominant cost is exploring valid partial boards and constructing each full board, which is exponential in the worst case.

Space Complexity: O(n) recursion depth, plus the board used to build answers. Excluding output storage, the auxiliary state is very small.

Algorithm name: Bitmask Backtracking with Branch-and-Bound.

Final Interview Takeaway

The fastest way to recognize this pattern is: “I need all valid arrangements, each level chooses one position, and every choice creates structural constraints for future levels.” That should immediately point you to backtracking with constraint tracking.
