LeetCode 735 — Asteroid Collision

Step 1 — Problem Statement

Input: You are given an array of non-zero integers, where each value represents one asteroid. The sign shows direction: positive means moving right, negative means moving left. The absolute value shows size.

Output: Return the final state of the asteroids after all collisions have been resolved.

Key Constraints: A collision can happen only when a right-moving asteroid is to the left of a left-moving asteroid. When two asteroids collide, the smaller one explodes. If both have the same size, both explode. Asteroids moving in the same direction never collide, and asteroids moving away from each other also never collide.

Edge Cases: Equal-sized asteroids destroying each other, chain reactions after a collision, all asteroids moving in one direction, a left-moving asteroid meeting multiple earlier right-moving asteroids, and sequences where no collision happens at all.

Step 2 — Problem Understanding & Approach Overview

This problem is really asking for a one-dimensional collision simulation with local interactions. The core challenge is not tracking positions in continuous space; it is deciding, for each new asteroid, which previously surviving asteroids it can still collide with.

Category: Stack / simulation.

Mental model: Scan from left to right and keep only the asteroids that are still “alive.” The only dangerous situation is when the current asteroid is moving left and the most recent alive asteroid is moving right. That is exactly the kind of “last-in, first-out” conflict a stack is designed for.

Common trap: Many candidates handle only one collision and forget chain reactions. A left-moving asteroid may destroy several right-moving asteroids in a row, so the resolution must continue until the conflict is truly gone.

Step 3 — Brute Force Solution

Naively, we can repeatedly scan the array, find the first colliding adjacent pair, resolve that pair, modify the array, and restart scanning until no more changes happen.

repeat changed = false scan from left to right: if asteroids[i] > 0 and asteroids[i + 1] < 0: resolve collision: if abs(left) > abs(right): remove right asteroid else if abs(left) < abs(right): remove left asteroid else: remove both asteroids changed = true break until changed == false

This works because every collision is eventually resolved, but it is inefficient. Each restart can rescan much of the array, and every erase can also shift elements. The bottleneck is repeated full rescanning after every collision.

Time Complexity: O(n²) in the worst case, because the array may be scanned many times and each pass may resolve only one collision.

Space Complexity: O(n), for the working array or temporary storage used during simulation.

Step 4 — Intuition Building

Test Case 1

Input: 5 10 -5

Current state: 5 and 10 are moving right, so they can safely stay together.
The next asteroid -5 moves left, so it can collide with the nearest surviving right-moving asteroid, which is 10.

Action: Compare 10 and -5. Since 10 is larger, -5 disappears.
Result: 5 10

This reveals the key pattern: a new left-moving asteroid only needs to fight with the most recent surviving right-moving asteroid, not with everything before it.

Test Case 2

Input: 8 -8

Current state: 8 moves right, -8 moves left, so they are heading toward each other.
Their sizes are equal.

Action: Both explode.
Result: empty

This is the rare edge case many implementations get wrong if they only check greater-than and less-than, but forget exact equality.

Test Case 3

Input: 10 2 -5

Current state after reading 10 2: both are moving right, so stack-like storage would be [10, 2].
The next asteroid -5 moves left, so it first collides with 2.

Action:
2 is smaller than 5, so 2 disappears.
Now -5 continues moving left and is still facing 10.
Compare 10 and -5: 10 is larger, so -5 disappears.

Result: 10

This is the main insight: one asteroid can trigger multiple collisions in a row. That is why a single if-condition is not enough; we need a loop that keeps resolving as long as the current asteroid is still alive and the top of the structure is a right-moving asteroid.

Signal to recognize this approach in the future: any problem with ordered elements moving in one dimension, local collisions, and chain reactions should immediately suggest a stack.

Step 5 — Optimized Solution

Algorithm name: Stack-based collision simulation.

The fully optimal solution uses a stack to store the asteroids that are still alive after processing the prefix seen so far. Every new asteroid is compared only against the top of the stack while a collision is possible.

vector<int> asteroidCollision(vector<int>& asteroids) { vector<int> st; for (int a : asteroids) { bool alive = true; while (alive && a < 0 && !st.empty() && st.back() > 0) { if (st.back() < -a) { st.pop_back(); } else if (st.back() == -a) { st.pop_back(); alive = false; } else { alive = false; } } if (alive) { st.push_back(a); } } return st; }

Why this works: the only possible collision is between a previous right-moving asteroid and the current left-moving asteroid. If the top of the stack is negative, both asteroids are moving left, so they never meet. If the current asteroid is positive, it is moving right and cannot collide with earlier asteroids because it is to the right of them and moving away.

Why the while loop is necessary: after one smaller asteroid explodes, the current asteroid may still survive and need to collide again with the next right-moving asteroid behind it. That is the chain reaction.

Dry Run: 10 2 -5

Pivot state is not needed here; instead, the stack represents the alive asteroids.

Step 1: Read 10
Stack: 10

Step 2: Read 2
Stack: 10 2

Step 3: Read -5
Top = 2, and 2 < 5, so 2 explodes.
Stack becomes: 10

Now -5 is still alive, and top = 10.
10 > 5, so -5 explodes.
Final Stack: 10

Dry Run: 8 -8

Step 1: Read 8
Stack: 8

Step 2: Read -8
Top = 8, and 8 == 8, so both explode.
Stack: empty

Dry Run: 1 -2 -2

Step 1: Read 1
Stack: 1

Step 2: Read -2
Top = 1, and 1 < 2, so 1 explodes.
Stack becomes empty.
Since -2 is still alive and no right-moving asteroid remains, push -2.
Stack: -2

Step 3: Read -2
Top is negative, so no collision is possible.
Stack: -2 -2

Time Complexity: O(n). Every asteroid is pushed at most once and popped at most once. Even though there is a while loop, the total number of pops across the entire run is bounded by n.

Space Complexity: O(n), for the stack of surviving asteroids in the worst case where no collisions happen.

Final Takeaway

Asteroid Collision is a classic example of “local conflict + chain reaction + ordered processing.” The correct mental move is to preserve only the alive prefix and let the most recent right-moving asteroid fight the new left-moving asteroid. Once you see that, the stack solution becomes natural rather than memorized.
