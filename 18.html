LeetCode 18 — 4Sum
Step 1 — Problem Statement

Input: An integer array nums and an integer target. We need to find all unique quadruplets [a, b, c, d] such that a + b + c + d = target.

Output: Return every distinct quadruplet without duplicates. The order of quadruplets does not matter.

Key Constraints: The same value may appear many times in the array, so duplicate quadruplets must be removed carefully. Also, the sum of four integers can overflow a 32-bit int, so the sum should be computed using a wider type such as long long.

Edge Cases: fewer than 4 elements; all elements identical; many duplicates; negative numbers mixed with positive numbers; no valid quadruplet; very large values near integer limits; already sorted or reverse-sorted input.

Step 2 — Problem Understanding & Approach Overview

This is really asking for all unique combinations of four numbers whose sum matches a target, while preventing repeated answers caused by duplicate values. The core challenge is not just finding one quadruplet, but finding all unique quadruplets efficiently.

Category: Array + Sorting + Two Pointers + Duplicate Handling.

Mental model: Sort the array first, then fix the first two numbers and use two pointers for the remaining two numbers. Sorting turns duplicate elimination and pointer movement into something deterministic.

Common trap: Candidates often either brute-force all 4 indices, which is too slow, or they forget to skip duplicates at one of the levels and end up returning repeated quadruplets. Another subtle trap is integer overflow when adding four integers.

Step 3 — Brute Force Solution

The naive way is to check every possible quadruplet using four nested loops, then store only unique results. 

Pseudo-code:

sort nums
use a set to store unique quadruplets

for i from 0 to n-1:
    for j from i+1 to n-1:
        for k from j+1 to n-1:
            for l from k+1 to n-1:
                if nums[i] + nums[j] + nums[k] + nums[l] == target:
                    insert sorted quadruplet into set

convert set to answer list
return answer

Time Complexity: O(n4) because we try every combination of four indices.

Space Complexity: O(m) for storing the unique quadruplets in a set, where m is the number of valid answers.

Bottleneck: The four nested loops. Even modest input sizes make this approach too slow.

    Fewer than 4 elements

The key insight appears after sorting: once the first two numbers are fixed, the remaining two numbers can be searched using the classic two-pointer pattern because the array is ordered. That removes one full loop compared to brute force.

In future problems, whenever you need all unique k-sums from an array and duplicate control matters, think immediately about sorting + fixed prefix + two pointers.

Step 5 — Optimized Solution

There is one meaningful optimized approach here: sort the array, fix two indices, and use two pointers for the remaining pair. This is the standard optimal interview solution for 4Sum.

Idea: After sorting, choose the first element with index i, the second element with index j, then search the remaining subarray with two pointers l and r. Skip duplicates at every level so the same quadruplet is never produced twice. 

Pseudo-code:

sort nums
answer = empty list

for i from 0 to n-4:
    if i > 0 and nums[i] == nums[i-1]:
        continue

    for j from i+1 to n-3:
        if j > i+1 and nums[j] == nums[j-1]:
            continue

        l = j+1
        r = n-1

        while l < r:
            sum = nums[i] + nums[j] + nums[l] + nums[r]

            if sum == target:
                add quadruplet to answer
                l++
                r--
                skip duplicate values at l
                skip duplicate values at r

            else if sum < target:
                l++
            else:
                r--

Dry Run on [1, 0, -1, 0, -2, 2], target = 0 

Sorted array: [-2, -1, 0, 0, 1, 2]

Pivot i = 0 → -2
  j = 1 → -1
    l = 2, r = 5
    Sum = -2 + -1 + 0 + 2 = -1
    Need bigger sum → l++

    l = 3, r = 5
    Sum = -2 + -1 + 0 + 2 = -1
    Need bigger sum → l++

    l = 4, r = 5
    Sum = -2 + -1 + 1 + 2 = 0
    Found quadruplet: [-2, -1, 1, 2]

Extreme Edge Case Handling: For inputs like [2, 2, 2, 2, 2] with target 8, duplicate skipping ensures only one quadruplet is returned. Without duplicate checks at i, j, l, and r, the same answer would appear many times.

Time Complexity: O(n3). Sorting costs O(n log n), but the dominant part is the nested choice of i and j, plus the linear two-pointer scan for each pair. That gives O(n3) overall.

Space Complexity: O(1) extra space, ignoring the output list. The algorithm only uses a few pointers and counters.

Algorithm Name: Sorting + Two Pointers with Duplicate Skipping. 

vector> fourSum(vector& nums, int target) {
    vector> ans;
    int n = nums.size();
    if (n < 4) return ans;

    sort(nums.begin(), nums.end());

    for (int i = 0; i < n - 3; i++) {
        if (i > 0 && nums[i] == nums[i - 1]) continue;

        for (int j = i + 1; j < n - 2; j++) {
            if (j > i + 1 && nums[j] == nums[j - 1]) continue;

            int l = j + 1, r = n - 1;

            while (l < r) {
                long long sum = 1LL * nums[i] + nums[j] + nums[l] + nums[r];

                if (sum == target) {
                    ans.push_back({nums[i], nums[j], nums[l], nums[r]});
                    l++;
                    r--;

                    while (l < r && nums[l] == nums[l - 1]) l++;
                    while (l < r && nums[r] == nums[r + 1]) r--;
                }
                else if (sum < target) {
                    l++;
                }
                else {
                    r--;
                }
            }
        }
    }

    return ans;
}
