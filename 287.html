Step 1 — Problem Statement

Input: An integer array nums of length n + 1, where every value is in the range 1..n. Exactly one number is duplicated, but that duplicate may appear more than twice.

Output: Return the duplicated number without modifying the array.

Key Constraints: The values are tightly bounded to 1..n, while the array has n + 1 elements. That mismatch is the core signal: by the pigeonhole principle, at least one value must repeat. The classic follow-up constraint for this problem is to use only O(1) extra space and less than O(n^2) time.

Edge Cases:

  • Minimum valid input such as [1, 1].
  • Duplicate appears at the beginning, middle, or end.
  • Duplicate appears more than twice, such as [2, 2, 2, 2] when valid under the range.
  • The array is already in a pattern that makes the duplicate appear immediately or only after a long chain.
  • You must not assume the duplicate is exactly twice; the same value can repeat many times.

Step 2 — Problem Understanding & Approach Overview

This problem is really asking: find the repeated value in a constrained array without using the normal “sort and compare” shortcut and without extra memory.

The core challenge is that the array is not just a list of numbers; because every value points to another valid index-like position, it can be treated as a functional graph with a guaranteed cycle.

Category: Array + Pigeonhole Principle + Cycle Detection.

Mental model: Think of each value as a pointer to the next index. The duplicate value creates a merge in that pointer structure, and a merge in a functional graph necessarily produces a cycle. Once you see that, the problem becomes a cycle-entry problem.

Subtle trap: Many candidates try to sort the array, mark values by negation, or use extra hash space immediately. Those approaches either violate the follow-up constraints or miss the deeper invariant: the duplicate is the entrance to a cycle.

Step 3 — Brute Force Solution

The most naive solution is to compare every element with every other element until you find a match. 

For i from 0 to n:
    For j from i + 1 to n:
        If nums[i] == nums[j]:
            return nums[i]

Why it works: If a number is duplicated, eventually some pair of equal values will be compared.

Time Complexity: O(n^2) — the outer loop runs roughly n times and the inner loop also runs up to n times.

Space Complexity: O(1) — no extra data structure is used.

Performance bottleneck: Rechecking already-seen values repeatedly. The same comparisons are done many times, which becomes too slow for large inputs.

Step 4 — Intuition Building

Test Case 1

Input: 1 3 4 2 2
    The values stay inside 1..4
    The duplicate is 2
Action: If we scan with extra memory, we would detect 2 when it appears the second time.
Result: 2

This is easy with a set, but it does not yet explain the deeper structure. The important observation is that values can be followed like links.

Test Case 2

Input: 3 1 3 4 2
    Start at index 0 and follow values as next hops
    3 → 4 → 2 → 3
    A cycle appears, and the duplicate value is where paths merge
Action: Notice that two different paths can arrive at the same value.
Result: The repeated value is 3

This is the key pattern: once two paths enter the same node, a cycle becomes inevitable. The duplicate is not just “a repeated number”; it is the entry point of the cycle.

Test Case 3 (Edge Case)

Input: 1 1
    Minimum valid size
    The duplicate is visible immediately
Action: Any correct O(1)-space solution must still handle this without special casing.
Result: 1

A weak solution sometimes assumes the cycle must be long. That is false. The optimal approach must also work when the meeting point happens almost instantly.

What signal should make you think of this approach in a future problem? When an array of bounded values can be interpreted as “next pointers,” and the problem guarantees one extra element or one guaranteed repetition, think cycle detection.

Step 5 — Optimized Solution

This problem has two distinct optimization levels:

First, you can reduce the brute force cost by storing seen values in a hash set. Then, you can go one step further and eliminate extra space entirely by using Floyd’s cycle detection.

Optimized Solution 1 (Intermediate) — Hash Set

Idea: Store each seen number. The first number that already exists in the set is the duplicate. 

Create an empty set
For each number x in nums:
    If x is already in set:
        return x
    Insert x into set

Time Complexity: O(n) — each element is inserted and checked once on average.

Space Complexity: O(n) — the set may store almost all elements before the duplicate is found.

What was eliminated: The repeated pairwise comparisons from brute force.

Optimized Solution 2 (Best Known / Fully Optimal) — Floyd’s Cycle Detection

Further insight: Because every value is in 1..n, you can treat nums[i] as a pointer to the next node. Starting from nums[0], you move through the graph until you enter the cycle. The duplicate number is the cycle entrance.

Algorithm name: Floyd’s Tortoise and Hare. 

int findDuplicate(vector<int>& nums) {
    int slow = nums[0];
    int fast = nums[0];

    do {
        slow = nums[slow];
        fast = nums[nums[fast]];
    } while (slow != fast);

    slow = nums[0];
    while (slow != fast) {
        slow = nums[slow];
        fast = nums[fast];
    }

    return slow;
}

Dry Run on 1 3 4 2 2

Phase 1 — Find meeting point
Start: slow = 1, fast = 1
Step 1: slow = nums[1] = 3, fast = nums[nums[1]] = nums[3] = 2
Step 2: slow = nums[3] = 2, fast = nums[nums[2]] = nums[4] = 2
Meeting point found at 2

Phase 2 — Find cycle entrance
Reset slow = 1, keep fast = 2
Step 1: slow = nums[1] = 3, fast = nums[2] = 4
Step 2: slow = nums[3] = 2, fast = nums[4] = 2
Both meet at 2
Final Result: 2

How this handles the edge case [1, 1]:
slow = 1, fast = 1 immediately meets in phase 1.
After reset, slow remains 1 and fast remains 1, so the entrance is returned correctly without any special handling.

Time Complexity: O(n). The tortoise and hare each move through at most a constant number of passes over the implicit graph. Phase 1 takes linear time to reach the cycle and detect a meeting point. Phase 2 also takes linear time in the worst case to reach the cycle entrance.

Space Complexity: O(1). Only two pointers are used, regardless of input size.

Final Interview Takeaway

The fastest way to recognize this problem is to notice that the value range is restricted to 1..n while the array has n + 1 elements. That mismatch guarantees a duplicate. Once you reinterpret values as pointers, the duplicate becomes a cycle entrance, and Floyd’s algorithm gives the clean O(n) time, O(1) space answer.
