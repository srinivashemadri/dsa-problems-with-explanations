LeetCode 1043 — Partition Array for Maximum Sum
Step 1 — Problem Statement

Input: You are given an integer array nums and an integer k. You may partition the array into contiguous subarrays, where each subarray has length at most k. For every subarray, all its elements are replaced by the maximum element in that subarray, and the score of that subarray becomes maximum element × subarray length.

Output: Return the maximum possible total score after partitioning the entire array.

Key Constraints: The partitions must be contiguous, every chosen block can have length from 1 to k, and every element must belong to exactly one block. The decision at one position affects all future choices, so local greediness is not enough.

Edge Cases: A single element array, k = 1, k ≥ n, all elements equal, strictly increasing or decreasing arrays, and cases where the best answer comes from mixing short and long partitions rather than using the same size everywhere.

Step 2 — Problem Understanding & Approach Overview

Strip away the story: at every index, decide how far to extend the current partition, knowing that every partition contributes its maximum value multiplied by its length.

The core challenge is choosing the best partition size at each position while preserving contiguity.

Category: Dynamic Programming, partition DP.

Mental model: Think from left to right. At index i, try ending the last block with length 1, 2, ..., k, compute that block’s value, and combine it with the best answer for the prefix before it.

Common trap: Greedy choices like “always take the largest possible block” or “always extend while the max increases” fail because a short block now may unlock a much better partition later.

Step 3 — Brute Force Solution

The naive idea is to recursively try every valid partition starting at each index. For each position, choose block length from 1 to k, compute the block score, and recurse on the remaining suffix. 

dfs(i):
    if i == n:
        return 0

    ans = 0
    maxVal = 0

    for len from 1 to k:
        if i + len - 1 >= n:
            break

        maxVal = max(maxVal, nums[i + len - 1])
        ans = max(ans, maxVal * len + dfs(i + len))

    return ans

Time Complexity: Exponential in the worst case, roughly O(k^n), because each index branches into up to k choices and the same suffixes are recomputed many times.

Space Complexity: O(n) recursion depth.

Performance bottleneck: Repeating the same subproblems for overlapping suffixes. That is exactly what DP removes.

Step 4 — Intuition Building
Test Case 1

Input: nums = [1], k = 1
    Only one possible block exists.
Action: Take the single element as one partition.
Result: 1

Test Case 2

Input: nums = [5, 5, 5], k = 3
    Every partition of any size has the same maximum: 5.
    A larger block always multiplies that same max by a larger length.
Action: Take the whole array as one block.
Result: 5 × 3 = 15

Test Case 3

Input: nums = [1, 15, 7, 9, 2, 5, 10], k = 3
    At the start, a short block can preserve a better structure later.
    For example, grouping [1, 15, 7] gives 15 × 3, but that is not automatically optimal globally.
Action: Try every block length 1..3 at each position and combine with the best prefix answer.
Result: The optimal total is 84.

The important discovery is that the best answer for a prefix only depends on earlier prefixes, not on the full partition history. That makes dynamic programming natural.

A rare but important edge case is k ≥ n. In that case, the best answer is often the entire array as one block, but not always by instinct alone — DP still handles it safely by checking all lengths up to min(k, i).

Signal for future problems: If a problem asks for the best score over a sequence with contiguous segments, and each segment’s value depends on the segment’s maximum/minimum/sum and its length, think partition DP.

Step 5 — Optimized Solution

There is one optimal solution family here: dynamic programming with memoization or tabulation. The fully optimal interview answer is bottom-up DP with O(nk) time.

Idea: Let dp[i] be the maximum score for the prefix nums[0..i-1]. To compute dp[i], consider the last block ending at position i-1 with length len from 1 to k. Track the maximum element in that block while expanding backward.

for i from 1 to n:
    maxVal = 0
    for len from 1 to k:
        if i - len < 0:
            break
        maxVal = max(maxVal, nums[i - len])
        dp[i] = max(dp[i], dp[i - len] + maxVal * len)

Why this works: The last partition must end at i-1. If its length is len, then everything before it is an independent optimal prefix problem. We only need the maximum inside that last block, which can be maintained while expanding the block backward.

Edge case handling: If k > n, the inner loop naturally stops when i - len < 0. If k = 1, the solution reduces to summing all elements, because only single-element partitions are allowed.

Time Complexity: O(nk), because for each index i, we try up to k partition lengths.

Space Complexity: O(n) for the DP array. It can be reduced to O(n) only in the straightforward form; further reduction is not useful because each state may depend on up to k previous states.

Algorithm Name: Dynamic Programming / Partition DP.

Full Working C++17 Code
int maxSumAfterPartitioning(vector& nums, int k) {
    int n = nums.size();
    vector dp(n + 1, 0);

    for (int i = 1; i <= n; ++i) {
        int maxVal = 0;

        for (int len = 1; len <= k; ++len) {
            if (i - len < 0) break;

            maxVal = max(maxVal, nums[i - len]);
            dp[i] = max(dp[i], dp[i - len] + maxVal * len);
        }
    }

    return dp[n];
}

The key interview takeaway is simple: the array is not being rearranged; it is being partitioned. Once you recognize “best answer for a prefix + bounded last segment,” the DP formulation becomes direct.
