Step 1 — Problem Statement

Input: A floating-point number x and an integer n. The task is to compute x^n, meaning x multiplied by itself n times when n is positive, and the reciprocal when n is negative.

Output: Return the value of x^n as a floating-point number.

Key Constraints: The exponent can be very large in magnitude, so a linear multiplication approach is too slow. Negative exponents must be converted into reciprocals. The implementation must also handle the extreme case where n = INT_MIN, because negating it directly overflows a 32-bit integer.

Edge Cases: Empty input does not apply here, but the meaningful corner cases do:

  • n = 0 — result should be 1 for any nonzero base.
  • x = 1 or x = -1 — results repeat predictably even for huge exponents.
  • x = 0 with positive exponent — result is 0.
  • n < 0 — must return 1 / x|n|.
  • n = INT_MIN — must avoid overflow while taking absolute value.
  • Very large |n| — recursion depth or repeated multiplication can become a problem if the approach is not logarithmic.
Step 2 — Problem Understanding & Approach Overview

Strip away the story: this is really asking for an efficient way to compute repeated multiplication using the structure of the exponent, not by multiplying one step at a time.

The core challenge is to reduce the number of multiplications from O(|n|) to O(log |n|).

Category: Binary exponentiation / divide-and-conquer / fast power.

Mental model: Think of the exponent in binary. Every bit tells you whether to include a particular power of the base. Squaring repeatedly gives you powers of x at exponentially growing scales.

Subtle trap: Many candidates convert n to abs(n) using an int. That breaks for INT_MIN because abs(INT_MIN) is not representable in 32-bit signed integer.

Step 3 — Brute Force Solution

The naive idea is to multiply x by itself |n| times, then invert the result if n is negative. 

if n == 0:
    return 1

isNegative = (n < 0)
power = absolute value of n
result = 1

repeat power times:
    result = result * x

if isNegative:
    return 1 / result
else:
    return result

Time Complexity: O(|n|). The loop runs once per unit of exponent.

Space Complexity: O(1). Only a constant number of variables are used.

Performance bottleneck: The repeated multiplication itself. For large exponents, this becomes far too slow.

Step 4 — Intuition Building

Test Case 1

Input: x = 2.0, n = 10
    Straight multiplication would do 10 multiplies
    But 10 in binary is 1010
Action: Use squaring to jump across powers
Result: 2^10 = 1024

What this reveals: The exponent can be decomposed into powers of two. Instead of building the answer one multiplication at a time, we can build the needed powers by squaring.

Test Case 2

Input: x = 2.0, n = -3
    Negative exponent means reciprocal
    2^-3 = 1 / 2^3
Action: First compute 2^3, then invert
Result: 0.125

What this reveals: Negative exponent is not a separate hard problem. Convert it once into a positive exponent problem, then handle the reciprocal at the end.

Test Case 3 (Edge Case)

Input: x = 2.0, n = INT_MIN
    abs(INT_MIN) overflows a 32-bit int
    Directly doing n = -n is unsafe
Action: Promote n to a larger type before negation
Result: computation remains correct

What this reveals: The solution must protect exponent conversion using a wider integer type such as long long.

The inefficiency in brute force is now obvious: most multiplications are wasted. If an exponent has 30 bits, we do not need 230 operations; we only need to inspect those 30 bits and square at each level.

Signal to recognize this approach in future problems: Whenever a problem asks for repeated multiplication, repeated application of an operation, or a power-like recurrence, think of binary exponentiation immediately.

Step 5 — Optimized Solution

There is one optimal idea here: binary exponentiation. It is already the fully optimal approach for this problem.

The key insight is simple: x^n can be broken into squares. If n is even, then x^n = (x2)n/2. If n is odd, then x^n = x * x^(n-1). This reduces the exponent by about half each step.

Optimized Solution — Binary Exponentiation (Iterative)

double myPow(double x, int n) {
    long long exp = n;
    if (exp < 0) {
        x = 1.0 / x;
        exp = -exp;
    }

    double result = 1.0;

    while (exp > 0) {
        if (exp & 1LL) {
            result *= x;
        }
        x *= x;
        exp >>= 1;
    }

    return result;
}

Dry Run

Input: x = 2.0, n = 10

Step 1 — Initialization
    exp = 10
    result = 1.0

Step 2 — exp = 10 (binary 1010)
    exp is even, so do not multiply result
    Square x: x = 4.0
    Shift exp: exp = 5

Step 3 — exp = 5 (binary 0101)
    exp is odd, so result *= x
    result = 1.0 * 4.0 = 4.0
    Square x: x = 16.0
    Shift exp: exp = 2

Step 4 — exp = 2 (binary 0010)
    exp is even, so result stays 4.0
    Square x: x = 256.0
    Shift exp: exp = 1

Step 5 — exp = 1 (binary 0001)
    exp is odd, so result *= x
    result = 4.0 * 256.0 = 1024.0
    Square x: x = 65536.0
    Shift exp: exp = 0

Final Result
    1024.0

How the extreme edge case is handled

Input: x = 2.0, n = INT_MIN

Step 1 — Promote exponent
    exp = (long long)n

Step 2 — Negate safely
    exp = -exp   // safe because exp is long long

Step 3 — Continue with binary exponentiation
    No overflow from absolute value conversion
    Final computation is correct

Time Complexity: O(log |n|). Each loop iteration halves the exponent by shifting right one bit. The number of iterations equals the number of bits in |n|.

Space Complexity: O(1). The iterative version uses constant extra space.

Algorithm name: Binary exponentiation, also called fast power or exponentiation by squaring.
