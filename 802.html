LeetCode 802 — Find Eventual Safe States
Step 1 — Problem Statement

Input: You are given a directed graph with n nodes labeled from 0 to n - 1, represented as an adjacency list. For each node, graph[i] contains all nodes reachable directly from i.

Output: Return all nodes that are eventually safe, sorted in ascending order. A node is eventually safe if every path starting from that node eventually ends at a terminal node instead of getting stuck in a cycle.

Key Constraints: This is a directed graph problem. The graph can be disconnected. A node may have zero outgoing edges, and that node is immediately safe. The critical condition is not “can reach a terminal node,” but “all possible paths must avoid cycles.”

Edge Cases: An empty graph, a single terminal node, a self-loop, a pure cycle, a chain leading into a cycle, and disconnected components where some parts are safe while others are not.

Step 2 — Problem Understanding & Approach Overview

Strip away the story: this problem is asking for all nodes that do not belong to, and do not lead into, any directed cycle. The core challenge is to identify nodes whose outgoing edges eventually all point to already-safe nodes.

This is a graph cycle-safety problem. The mental model is to think backwards: start from terminal nodes, mark them safe, then keep removing nodes whose outgoing neighbors are all safe. The subtle trap is to explore from each node and think “if one path reaches a terminal, the node is safe.” That is wrong. A node is safe only if every path from it finishes without entering a cycle.

Step 3 — Brute Force Solution

The most naive approach is: for every node, run a fresh DFS and check whether any path from that node reaches a cycle. If a cycle is found on any path, mark the node unsafe; otherwise mark it safe. Without memoization, the same subgraphs are explored again and again. 

Naive idea:
for each node u:
    run DFS from u with a fresh visited set
    if DFS detects a cycle on any path:
        u is unsafe
    else:
        u is safe

DFS(u):
    if u is already in current recursion stack:
        cycle found
    if u has no outgoing edges:
        safe
    mark u in current recursion stack
    for each v in graph[u]:
        if DFS(v) says cycle:
            return unsafe
    remove u from recursion stack
    return safe

Time Complexity: O(V * (V + E)) in the naive version, because you may traverse most of the graph again for each start node.

Space Complexity: O(V) for the recursion stack and visited structure used during one DFS run.

Bottleneck: repeated exploration of the same nodes and edges from many different starting points.

Step 4 — Intuition Building

Test Case 1

Input: [ [1,2], [2,3], [5], [0], [5], [], [] ]
    Node 5 and 6 are terminal.
    The useful question is not “who can reach a terminal?” but “who becomes safe only after all outgoing neighbors are safe?”
Action: Start from terminal nodes and peel backward.
Result: Safe nodes are 2, 4, 5, 6.

Test Case 2

Input: [ [1], [2], [0] ]
    Every node belongs to a cycle.
    No terminal node exists, so nothing can be peeled.
Action: The queue of terminal nodes starts empty.
Result: No safe nodes.

Test Case 3 (Edge Case)

Input: [ [0], [] ]
    Node 0 has a self-loop, so it is immediately unsafe.
    Node 1 is terminal, so it is safe.
Action: Mark only terminal nodes first; never let a self-loop node become safe unless its outgoing count drops to zero, which will never happen here.
Result: Safe nodes are 1 only.

The pattern to notice in future problems is: terminal states + nodes that become valid only after all outgoing neighbors are valid. That is the signal to think of reverse graph traversal and topological peeling.

Step 5 — Optimized Solution

This problem has one clean optimal solution: reverse the graph and run Kahn’s algorithm from terminal nodes. Instead of asking “which nodes can reach a cycle?”, ask “which nodes can be proven safe by eliminating all outgoing danger?” A node becomes safe only when every node it points to is already safe.

This is essentially topological trimming on the reversed graph. 

vector<int> eventualSafeNodes(vector<vector<int>>& graph) {
    int n = graph.size();
    vector<vector<int>> rev(n);
    vector<int> outdeg(n, 0);
    queue<int> q;

    for (int u = 0; u < n; ++u) {
        outdeg[u] = graph[u].size();
        for (int v : graph[u]) {
            rev[v].push_back(u);
        }
    }

    for (int i = 0; i < n; ++i) {
        if (outdeg[i] == 0) q.push(i);
    }

    vector<int> safe;
    while (!q.empty()) {
        int node = q.front();
        q.pop();
        safe.push_back(node);

        for (int parent : rev[node]) {
            if (--outdeg[parent] == 0) {
                q.push(parent);
            }
        }
    }

    sort(safe.begin(), safe.end());
    return safe;
}

Why this works

A node is unsafe only if it can reach a cycle. In reverse, a node is safe if all of its outgoing neighbors have already been proven safe. That gives us a dependency-removal process:

terminal nodes are safe first; then any node whose outgoing count drops to zero becomes safe next; then its parents may become safe; and so on.

Dry Run on the main sample

Input: [ [1,2], [2,3], [5], [0], [5], [], [] ]
Initial outdegree: 0:2, 1:2, 2:1, 3:1, 4:1, 5:0, 6:0
Initial queue: [5, 6]

Pivot / Start: nodes 5 and 6 are terminal, so they are safe immediately.
Process 5: parents are 2 and 4.
    outdeg[2]: 1 → 0, so push 2.
    outdeg[4]: 1 → 0, so push 4.
Process 6: no parents.
Process 2: parents are 0 and 1.
    outdeg[0]: 2 → 1.
    outdeg[1]: 2 → 1.
Process 4: parent is 1.
    outdeg[1]: 1 → 0, so push 1.
Process 1: parent is 0.
    outdeg[0]: 1 → 0, so push 0.
Process 0: no more useful parents.
Final safe set: [2, 4, 5, 6]

How the self-loop edge case behaves

For [ [0], [] ], only node 1 starts in the queue. Node 0 never enters it, because its outgoing edge points back to itself, so its outdegree never becomes zero. That is exactly the correct behavior.

Time Complexity: O(V + E). Building the reverse graph touches every edge once. The queue process also removes each node once and inspects each reversed edge once.

Space Complexity: O(V + E). The reverse graph stores all edges, and the queue / outdegree arrays store O(V) extra data.

Algorithm Name: Reverse graph + Kahn’s algorithm on outdegree.
