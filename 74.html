LeetCode 74 — Search a 2D Matrix
Step 1 — Problem Statement

Input: A matrix of integers and a target value. The matrix has two important properties: each row is sorted in non-decreasing order, and the first integer of every row is greater than the last integer of the previous row.

Output: Return whether the target exists in the matrix.

Key Constraints: The ordering is not just row-wise; the entire matrix behaves like one sorted sequence if read left to right, top to bottom. That structure is the real leverage point.

Edge Cases: empty matrix, empty row, single-element matrix, target smaller than the first element, target larger than the last element, target exactly at a row boundary, and matrices with only one row or one column.

Step 2 — Problem Understanding & Approach Overview

This is not really a “2D search” problem. It is a sorted-array search disguised inside a matrix. Because every row is sorted and each row starts after the previous row ends, the whole matrix can be treated as one ascending array.

Core challenge: locate the target without scanning every cell.

Category: Binary search / array transformation.

Mental model: imagine flattening the matrix into a virtual 1D sorted array, but without actually creating that array.

Common trap: many candidates do binary search on each row or linearly scan rows first, which wastes the sorted structure. The elegant move is to use one binary search over the virtual flattened index space.

Step 3 — Brute Force Solution

The naive approach is to inspect every element until the target is found or the matrix ends.

for each row in matrix:
    for each value in row:
        if value == target:
            return true
return false

Why it works: every cell is checked, so if the target exists, it will eventually be found.

Time Complexity: O(mn), where m is the number of rows and n is the number of columns.

Space Complexity: O(1), because no extra data structure is used.

Bottleneck: the full scan. It ignores the sorted structure completely.

The key discovery is that the matrix already has global sorted order. The row boundaries are not a problem; they are just index mapping details. A future problem should trigger the same approach when a 2D structure is sorted in a way that allows a virtual 1D ordering.

Step 5 — Optimized Solution

This problem has one meaningful optimal solution: perform binary search over the matrix as if it were a single sorted array.

Idea: use a virtual index from 0 to m*n - 1. Convert each virtual index into row and column using:

row = mid / n
col = mid % n

Then compare matrix[row][col] with the target and shrink the search space exactly like standard binary search.

Algorithm Name: Binary Search on a Flattened Sorted Matrix.

bool searchMatrix(vector>& matrix, int target) {
    int m = matrix.size();
    if (m == 0) return false;

    int n = matrix[0].size();
    if (n == 0) return false;

    int left = 0, right = m * n - 1;

    while (left <= right) {
        int mid = left + (right - left) / 2;
        int row = mid / n;
        int col = mid % n;
        int value = matrix[row][col];

        if (value == target) return true;
        if (value < target) left = mid + 1;
        else right = mid - 1;
    }

    return false;
}

Extreme Edge Case Handling:

Input: matrix = [ [10] ], target = 7

left = 0, right = 0
mid = 0
row = 0 / 1 = 0
col = 0 % 1 = 0

10 > 7

Search ends

Time Complexity: O(log(mn)). The search space has m*n elements conceptually, and each step halves that space.

Space Complexity: O(1). Only a few integer variables are used.

Step 6 — Final Answer

The fastest clean solution is a single binary search over the matrix treated as a virtual sorted array. That is the entire trick. No extra data structure, no row-by-row scan, no nested search.
