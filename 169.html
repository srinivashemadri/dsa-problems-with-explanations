LeetCode 169 — Majority Element
Step 1 — Problem Statement

Input: An integer array nums. The key guarantee is that a majority element exists. A majority element is one that appears more than ⌊n / 2⌋ times.

Output: Return that majority element.

Key Constraints: The array may contain duplicates, negative numbers, and the majority element may be scattered across the array rather than appearing in one contiguous block. Because the majority is guaranteed to exist, we do not need to handle the “no majority element” case in the final answer.

Edge Cases: single-element array, all elements identical, majority appearing only slightly more than half the time, elements alternating heavily, and values with large magnitude or negative values. A common interview trap is assuming the majority must be obvious from the first few elements; it may only become clear after cancellation across the full array.

Step 2 — Problem Understanding & Approach Overview

This problem is really asking: among all values in the array, which one survives after every other value is “outvoted” by the rest?

The core algorithmic challenge is finding the majority element without using extra space for full frequency counting.

Category: array, greedy, voting / cancellation.

Mental Model: Think of each different number as a candidate in an election. Whenever two different numbers meet, they cancel each other out. A true majority element cannot be fully canceled, because it appears more than all others combined.

Subtle Trap: Many candidates jump straight to hashing. That works, but it misses the deeper invariant: the majority element can be found in one pass with constant space using cancellation. Another trap is forgetting that this elegant one-pass candidate selection works because the problem guarantees a majority exists.

Step 3 — Brute Force Solution

The naive idea is to count the frequency of every element by comparing it with all others, then return the one whose count exceeds ⌊n / 2⌋. 

for i from 0 to n - 1:
    count = 0
    for j from 0 to n - 1:
        if nums[j] == nums[i]:
            count++
    if count > n / 2:
        return nums[i]

Why it works: For each candidate element, we compute its total frequency and check whether it is a majority.

Time Complexity: O(n²), because for each element we scan the entire array again.

Space Complexity: O(1), because we only store a few counters.

Performance Bottleneck: Recomputing frequencies from scratch for each index is wasteful. The same comparisons are repeated many times.

Step 4 — Intuition Building

The key insight is cancellation. A majority element appears more times than all other values combined, so even after pairing off different values, some copies of it must remain.

Test Case 1

Input: 3
    Only one element
    That element is automatically the majority
Action: Return 3
Result: 3

Test Case 2

Input: 2 2 1 1 1 2 2
    Early counts look mixed
    But 2 appears 4 times, which is more than 7/2 = 3
Action: Pair off different values mentally
    2 cancels with 1 several times
    One extra 2 still remains
Result: 2

Test Case 3 (Edge Case)

Input: 1 2 1 2 1
    Alternating pattern
    Majority is not obvious locally
    1 appears 3 times out of 5
Action: Cancel different pairs:
    1 vs 2 -> cancel
    1 vs 2 -> cancel
    leftover: 1
Result: 1

This cancellation view is the signal to think of the same approach in future problems: when one element is guaranteed to dominate more than half the array, look for a voting or pairing strategy instead of full counting.

Step 5 — Optimized Solution

There is one optimal solution here: Boyer-Moore Majority Vote Algorithm. It finds a candidate in one pass using cancellation, and because the problem guarantees a majority element exists, that candidate is the answer.

Core Idea: Keep one current candidate and a counter. When the current number matches the candidate, increase the counter. When it differs, decrease the counter. If the counter drops to zero, replace the candidate with the current number.

Why this is correct: Every mismatch cancels one vote of the current candidate. Since the majority element has more than half the total votes, it cannot be completely canceled.

Pseudocode

candidate = 0
count = 0

for x in nums:
    if count == 0:
        candidate = x
        count = 1
    else if x == candidate:
        count++
    else:
        count--

return candidate

Full Working C++17 Code

int majorityElement(vector<int>& nums) {
    int candidate = 0;
    int count = 0;

    for (int x : nums) {
        if (count == 0) {
            candidate = x;
            count = 1;
        } else if (x == candidate) {
            count++;
        } else {
            count--;
        }
    }

    return candidate;
}

Dry Run

Input: 2 2 1 1 1 2 2

Start:
    candidate = 0, count = 0

Step 1: x = 2
    count == 0
    candidate = 2, count = 1

Step 2: x = 2
    x == candidate
    count = 2

Step 3: x = 1
    x != candidate
    count = 1

Step 4: x = 1
    x != candidate
    count = 0

Step 5: x = 1
    count == 0
    candidate = 1, count = 1

Step 6: x = 2
    x != candidate
    count = 0

Step 7: x = 2
    count == 0
    candidate = 2, count = 1

Final Result: 2

Notice what happened: the counter went up for matching votes and down for opposing votes. The majority element eventually reasserted itself after cancellations.

How this handles the extreme edge case: In a single-element array like [7], the candidate becomes 7 immediately and remains 7. In a heavily alternating array, repeated cancellations may reset the candidate several times, but the true majority still survives by the end.

Time Complexity: O(n), because we make one linear pass through the array.

Space Complexity: O(1), because only a candidate and a counter are maintained.
