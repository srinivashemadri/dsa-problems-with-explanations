Step 1 — Problem Statement

Input: An integer array nums. We need to find all values that appear more than ⌊n / 3⌋ times, where n is the length of the array.

Output: Return all such elements in any order. There can be at most two elements satisfying this condition.

Key Constraints: The threshold is strict: the element must appear more than ⌊n/3⌋ times, not equal to it. Since each qualifying number must take up more than one-third of the array, there can never be more than two answers.

Edge Cases: empty array, single element, two elements, all elements identical, no majority element at all, exactly one qualifying element, exactly two qualifying elements, and arrays where the two candidates interfere with each other during elimination.

Step 2 — Problem Understanding & Approach Overview

This problem is really asking for every number whose frequency is greater than one-third of the array length. The story is just packaging; the real task is frequency detection under a tight threshold.

The core challenge is that a full frequency map is easy, but the interview-level insight is that we can do better in space by exploiting the fact that there can be at most two valid answers.

Category: Array, Counting, Boyer-Moore Majority Vote generalization.

Mental model: Think of each number as competing for survival. Every time a new number appears that is different from both current candidates, it can cancel one count from each candidate. Only numbers with truly heavy support can survive this pruning.

Subtle trap: Many candidates stop after the elimination pass and return the surviving candidates directly. That is wrong, because survivors are only potential answers; they must be verified with a second counting pass.

Step 3 — Brute Force Solution

The naive approach is to count the frequency of every distinct value using a hash map, then collect those whose frequency is greater than ⌊n/3⌋. 

pseudocode:
create empty map freq
for each x in nums:
    freq[x]++

create empty result
for each (value, count) in freq:
    if count > n/3:
        add value to result

return result

Why it works: We directly compute the exact frequency of each number and filter by the required threshold.

Time Complexity: O(n) average, because we scan the array once and then scan the distinct keys once more.

Space Complexity: O(n) in the worst case, when all elements are distinct.

Performance bottleneck: The frequency map stores potentially every distinct number, which is unnecessary when we know there can be at most two answers.

Step 4 — Intuition Building

Test Case 1

Input: 3 2 3
    n = 3, threshold = > 1
    3 appears twice, 2 appears once
Action: Count frequencies or observe that 3 clearly crosses the threshold
Result: [3]

Test Case 2

Input: 1 1 1 3 3 2 2 2
    n = 8, threshold = > 2
    1 appears 3 times, 2 appears 3 times, 3 appears 2 times
Action: Both 1 and 2 qualify; 3 does not
Result: [1, 2]

Test Case 3 (Edge Case)

Input: 1 2 3 4
    n = 4, threshold = > 1
    No number appears more than once
Action: Count frequencies and reject all values
Result: []

From these cases, the key insight appears naturally: only a tiny number of values can ever survive the threshold. Since the limit is n/3, the answer size is at most two. That means we do not need to keep all counts forever; we only need two moving candidates and a way to cancel weak contenders.

The extreme edge case is an array where every value is different. A naive frequency map still works, but the optimal method will repeatedly eliminate candidates and end with no verified answer, which is exactly correct.

Future signal: If a problem asks for elements appearing more than n/k times and k is small, immediately think of the generalized Boyer-Moore voting pattern.

Step 5 — Optimized Solution

There is one meaningful optimal solution here: the Boyer-Moore Majority Vote generalization for the n/3 threshold. The first pass finds up to two potential candidates by cancellation. The second pass verifies them.

Optimized Idea: Since there can be at most two valid numbers, keep two candidate slots and two counters. When a new number matches one candidate, increase that counter. If it matches neither and there is an empty slot, place it there. Otherwise, decrease both counters, because three different values can neutralize one another.

pseudocode:
candidate1, candidate2 = null, null
count1, count2 = 0, 0

for each x in nums:
    if x == candidate1:
        count1++
    else if x == candidate2:
        count2++
    else if count1 == 0:
        candidate1 = x
        count1 = 1
    else if count2 == 0:
        candidate2 = x
        count2 = 1
    else:
        count1--
        count2--

reset count1, count2 to 0

for each x in nums:
    if x == candidate1:
        count1++
    else if x == candidate2:
        count2++

result = empty list
if count1 > n/3: add candidate1
if candidate2 is different from candidate1 and count2 > n/3: add candidate2

return result

Dry Run

Input: 1 1 1 3 3 2 2 2
Pivot concept does not apply here; the logic is candidate survival.

Pass 1 — Candidate Selection

Step 1: x = 1
    candidate1 empty → candidate1 = 1, count1 = 1

Step 2: x = 1
    matches candidate1 → count1 = 2

Step 3: x = 1
    matches candidate1 → count1 = 3

Step 4: x = 3
    candidate2 empty → candidate2 = 3, count2 = 1

Step 5: x = 3
    matches candidate2 → count2 = 2

Step 6: x = 2
    matches neither; both counts positive → count1 = 2, count2 = 1

Step 7: x = 2
    matches neither; both counts positive → count1 = 1, count2 = 0

Step 8: x = 2
    candidate2 empty → candidate2 = 2, count2 = 1

Pass 2 — Verification
Count occurrences: 1 → 3, 2 → 3
Threshold: > 8/3 = > 2
Final Result: [1, 2]

Edge Case Dry Run

Input: 1 2 3 4
    After cancellation, candidates may remain temporarily, but verification counts them as only 1 each.
    Threshold is > 1, so none qualify.
Result: []

Time Complexity: O(n). The first pass scans once, and the verification pass scans once more. Each operation inside the loop is O(1).

Space Complexity: O(1). Only two candidates and two counters are stored, regardless of input size.

Algorithm Name: Boyer-Moore Majority Vote, generalized for the n/3 case.

Full Working C++17 Code

vector<int> majorityElement(vector<int>& nums) {
    int cand1 = 0, cand2 = 1;
    int count1 = 0, count2 = 0;

    for (int x : nums) {
        if (x == cand1) {
            count1++;
        } else if (x == cand2) {
            count2++;
        } else if (count1 == 0) {
            cand1 = x;
            count1 = 1;
        } else if (count2 == 0) {
            cand2 = x;
            count2 = 1;
        } else {
            count1--;
            count2--;
        }
    }

    count1 = 0;
    count2 = 0;

    for (int x : nums) {
        if (x == cand1) count1++;
        else if (x == cand2) count2++;
    }

    vector<int> result;
    int n = nums.size();

    if (count1 > n / 3) result.push_back(cand1);
    if (cand2 != cand1 && count2 > n / 3) result.push_back(cand2);

    return result;
}
Step 6 — Final Takeaway

The key idea is not “find the most frequent numbers.” It is “use the fact that there can be at most two answers, eliminate weak contenders in pairs, and then verify the survivors.”

The moment you see a frequency threshold of more than n/3, the right instinct is to think beyond a map and reach for the two-candidate voting pattern.
