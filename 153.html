LeetCode 153 — Find Minimum in Rotated Sorted Array
Based on the uploaded prompt for this problem :contentReference[oaicite:0]{index=0}, the task is to find the minimum element in a rotated sorted array with no duplicates.
Step 1 — Problem Statement
Input: An integer array nums that was originally sorted in strictly increasing order and then rotated at some unknown pivot. The array contains no duplicate values.
Output: Return the minimum element in the array.
Key Constraints: The array is non-empty, sorted before rotation, and has distinct values. Those constraints are exactly what make binary search possible.
Edge Cases:
• Array of size 1.
• Array not rotated at all, for example 1 2 3 4.
• Fully rotated back to the original order, which is the same as not rotated.
• Pivot at index 0 or at the last possible split position.
• No duplicates means comparisons stay unambiguous; this is important because the duplicate version is harder.
Step 2 — Problem Understanding & Approach Overview
This is really asking: where is the smallest value located in a sorted array that has been rotated? The core challenge is not to sort, but to detect which half must contain the minimum using comparisons.
Category: Binary Search on a rotated sorted array.
Mental Model: Imagine two sorted halves glued together. One side is still in increasing order, and the other side contains the rotation break. The minimum is exactly at the break.
Common Trap: Many candidates compare against the left boundary and get tangled in cases where the minimum is on the right. The cleanest invariant here is to compare nums[mid] with nums[right].
Step 3 — Brute Force Solution
The naive idea is simple: scan the whole array and keep track of the smallest element. 
minVal = nums[0]
for each x in nums:
    if x < minVal:
        minVal = x
return minVal
Time Complexity: O(n), because every element is inspected once.
Space Complexity: O(1), because only one variable is used.
Bottleneck: We ignore the sorted structure completely, so we pay linear time even though the input has enough order to do better.
Step 4 — Intuition Building
Test Case 1
Input: 4 5 6 7 0 1 2
Array is split into two monotonic parts.
Observation: The minimum is in the right half because 0 is smaller than the elements before it.
Action: Compare middle with right boundary. If nums[mid] > nums[right], the minimum must be to the right of mid.
Result: We discard the left sorted part and keep narrowing toward the pivot.
Test Case 2
Input: 1 2 3 4 5
Already sorted, no rotation.
Observation: Every middle element will be less than or equal to the right boundary, so the minimum must stay on the left side, possibly at the current left boundary.
Action: Move the right boundary leftward.
Result: Search collapses to index 0, which is the answer.
Test Case 3 (Edge Case)
Input: 2
Single element.
Observation: There is nothing to compare.
Action: Return the only value.
Result: 2
The important pattern is this: in a rotated sorted array with distinct values, one half is always sorted. By comparing the middle element to the right boundary, we can tell which side still contains the rotation point. That is the key signal for binary search in future problems.
Step 5 — Optimized Solution
This problem has one meaningful optimized solution: binary search.
Optimized Solution
Idea: Keep shrinking the search space while preserving the invariant that the minimum lies inside [left, right].
Use this rule:
• If nums[mid] > nums[right], the minimum is strictly to the right of mid.
• Otherwise, the minimum is at mid or to its left.
This works because the right side tells us whether mid is in the left sorted block or the right sorted block.
Pseudocode: 
left = 0
right = n - 1

while left < right:
    mid = left + (right - left) / 2

    if nums[mid] > nums[right]:
        left = mid + 1
    else:
        right = mid

return nums[left]
Dry Run:
Input: 4 5 6 7 0 1 2
Initial: left = 0, right = 6
Pivot is somewhere in the right side.
Step 1: mid = 3, nums[mid] = 7, nums[right] = 2
7 > 2, so the minimum must be to the right of mid.
Update: left = 4
Step 2: left = 4, right = 6, mid = 5, nums[mid] = 1, nums[right] = 2
1 <= 2, so the minimum is at mid or to the left of mid.
Update: right = 5
Step 3: left = 4, right = 5, mid = 4, nums[mid] = 0, nums[right] = 1
0 <= 1, so keep the left half.
Update: right = 4
Final Result: left = right = 4, answer = 0
Extreme Edge Case Handling:
• For 1 2 3 4 5, the condition nums[mid] > nums[right] is never true, so the search keeps moving left until it reaches index 0.
• For a single element array, the loop never runs and the only element is returned immediately.
Time Complexity: O(log n), because each comparison cuts the search interval roughly in half.
Space Complexity: O(1), because the algorithm uses only a few variables.
Algorithm Name: Binary Search on Rotated Sorted Array.
Full Working C++17 Code
int findMin(vector<int>& nums) {
    int left = 0, right = (int)nums.size() - 1;

    while (left < right) {
        int mid = left + (right - left) / 2;

        if (nums[mid] > nums[right]) {
            left = mid + 1;
        } else {
            right = mid;
        }
    }

    return nums[left];
}
The signal to recognize in future problems is: “a sorted array has been disturbed exactly once, and I need the boundary of the disturbance.” That almost always points to a binary search on the partition point rather than a full scan.
