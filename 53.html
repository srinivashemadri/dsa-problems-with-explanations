LeetCode 53 — Maximum Subarray
Step 1 — Problem Statement

Input: An integer array nums, where each element may be positive, negative, or zero.

Output: Return the maximum possible sum of any non-empty contiguous subarray.

Key Constraints: The subarray must be continuous, and you must choose at least one element. That single rule is what changes the problem from “sum of any elements” to a true interval problem.

Edge Cases: all numbers negative, a single-element array, all numbers positive, mixed positive and negative values, zeros inside the array, and cases where the best subarray starts or ends at the boundary.

Step 2 — Problem Understanding & Approach Overview

This problem is really asking: among all contiguous segments of the array, which one has the largest sum?

The core algorithmic challenge is deciding whether to extend the current segment or discard it and start fresh at the current index.

This is a classic dynamic programming / greedy style problem.

Mentally, you should see it like this: as you scan left to right, every position forces a decision — is the best subarray ending here built from the previous best ending here, or is the previous baggage so bad that you should restart here?

The subtle trap is assuming that once the running sum becomes negative, you can still salvage it later. You usually cannot. A negative prefix only hurts future sums, so the optimal strategy is to drop it immediately.

Step 3 — Brute Force Solution

The most naive idea is to try every possible subarray, compute its sum, and keep the maximum.

for i from 0 to n-1:
    sum = 0
    for j from i to n-1:
        sum += nums[j]
        ans = max(ans, sum)
return ans

Each starting point i expands to the right and checks every ending point j. That covers all contiguous subarrays, but it repeats a lot of work.

Time Complexity: O(n²). There are O(n) starting points and for each one we may scan O(n) elements.

Space Complexity: O(1). We only store a few variables.

The performance bottleneck is obvious: the same partial sums are recomputed again and again.

Step 4 — Intuition Building

Test Case 1

Input: -2 1 -3 4 -1 2 1 -5 4
    Negative prefixes keep hurting future sums
    Best segment should be discovered by dropping bad baggage early
Action: Keep a running sum, but restart whenever the running sum becomes harmful
Result: 6, from subarray 4 -1 2 1

Test Case 2

Input: -5 -2 -8
    Every number is negative
    The maximum subarray is still required to be non-empty
Action: Never return 0; pick the largest single element
Result: -2

Test Case 3

Input: 1 2 3
    Running sum keeps improving
    No reason to restart
Action: Extend the current subarray all the way
Result: 6

The key insight emerges naturally: a subarray with a negative running sum can never help a future subarray become larger. If the current total is below zero, carrying it forward is worse than starting from the next element.

The signal that should immediately make you think of this approach is: “maximum sum of a contiguous segment” with repeated decisions to either continue or restart.

Step 5 — Optimized Solution

This problem has one fully optimal standard solution: Kadane’s Algorithm.

The idea is simple: at every position, maintain the best subarray sum ending exactly at that position. That value is either the current element alone, or the current element plus the best ending at the previous position.

Pseudocode:

bestEndingHere = nums[0]
bestSoFar = nums[0]

for each element nums[i] from index 1 to end:
    bestEndingHere = max(nums[i], bestEndingHere + nums[i])
    bestSoFar = max(bestSoFar, bestEndingHere)

return bestSoFar

Why this works: if the best sum ending at the previous index is negative, extending it only makes the current sum worse. So the algorithm chooses between starting fresh at the current element or extending the previous segment.

Edge Case Handling: for an all-negative array like -5 -2 -8, initialization with the first element is essential. It ensures the answer is the largest negative number rather than incorrectly returning 0.

Time Complexity: O(n). We scan the array once, and each step does constant work.

Space Complexity: O(1). Only two variables are maintained.

Algorithm Name: Kadane’s Algorithm.

Step 6 — C++ Code
int maxSubArray(vector<int>& nums) {
    int bestEndingHere = nums[0];
    int bestSoFar = nums[0];

    for (int i = 1; i < (int)nums.size(); ++i) {
        bestEndingHere = max(nums[i], bestEndingHere + nums[i]);
        bestSoFar = max(bestSoFar, bestEndingHere);
    }

    return bestSoFar;
}
