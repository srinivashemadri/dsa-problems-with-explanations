LeetCode 1482 — Minimum Number of Days to Make m Bouquets
This walkthrough follows the requested interview-style structure from the uploaded instructions :contentReference[oaicite:0]{index=0}.
Step 1 — Problem Statement

Input: You are given an integer array bloomDay, where bloomDay[i] is the day the i-th flower blooms, along with two integers m and k. A bouquet can be made only by using k adjacent flowers that have all bloomed by the same day.

Output: Return the minimum day on which it is possible to make at least m bouquets. If it is impossible, return -1.

Key Constraints: The answer is a day value, not an index. The bloom days can be very large, so the search space is over possible days, not over array positions. Adjacent flowers matter, and once a flower is used in one bouquet, it cannot be reused in another.

Edge Cases: If m × k > n, it is impossible immediately. If all flowers bloom very late, the answer may be the maximum bloom day. If all flowers bloom early, the answer may be the minimum bloom day. If there are gaps of unbloomed flowers, the adjacency chain breaks. A single flower cannot contribute to a bouquet unless k = 1. If the array is already fully bloomed by some day, counting must still respect disjoint groups of size k.

Step 2 — Problem Understanding & Approach Overview

Strip away the story, and this becomes: find the smallest day such that the array contains at least m disjoint groups of k consecutive elements whose values are all ≤ that day.

The core challenge is not building bouquets once; it is deciding the earliest day when the condition becomes true. This is a classic binary search on answer problem.

Category: Binary Search on Answer + Greedy Feasibility Check.

Mental model: Imagine turning days into a threshold. For any day D, mark every flower that has bloomed by then. Now greedily count how many bouquets of length k you can extract from the consecutive bloomed stretches.

Subtle trap: Many candidates either try to simulate bouquet creation day by day, which is far too slow, or they count bloomed flowers without respecting adjacency and disjointness. The key is that feasibility is monotonic: if day D works, then any later day also works.

Step 3 — Brute Force Solution

The most naive idea is to try every possible day from the minimum bloom day to the maximum bloom day, and for each day, check whether we can form at least m bouquets. 

for day from min(bloomDay) to max(bloomDay):
    count bouquets by scanning the whole array
    if bouquets >= m:
        return day
return -1

During the scan for a fixed day, count consecutive flowers with bloomDay[i] ≤ day. Every time the streak reaches k, form one bouquet and reset the streak.

Time Complexity: O(R × n), where R = max(bloomDay) - min(bloomDay) + 1. This is terrible when bloom days are large, because the range can be up to 109.

Space Complexity: O(1).

Bottleneck: Repeating a full array scan for every possible day. The value range is what kills this approach.

Step 4 — Intuition Building

Test Case 1

Input: bloomDay = [1, 10, 3, 10, 2], m = 3, k = 1
    Since k = 1, every bloomed flower can be one bouquet.
    We only need to know how many flowers have bloomed by a given day.

Action:
    Day 1 -> bloomed flowers = [1, 0, 0, 0, 0] -> bouquets = 1
    Day 2 -> bloomed flowers = [1, 0, 0, 0, 1] -> bouquets = 2
    Day 3 -> bloomed flowers = [1, 0, 1, 0, 1] -> bouquets = 3

Result:
    Minimum day = 3

Test Case 2

Input: bloomDay = [7, 7, 7, 7, 12, 7, 7], m = 2, k = 3
    We need two disjoint groups of 3 adjacent bloomed flowers.
    Notice the flower with day 12 creates a gap until day 12.

Action:
    Day 7 -> bloomed = [1, 1, 1, 1, 0, 1, 1]
             consecutive bloomed stretches: [1,1,1,1] and [1,1]
             bouquets from first stretch = 1
             bouquets from second stretch = 0
             total = 1

    Day 12 -> bloomed = [1, 1, 1, 1, 1, 1, 1]
              one full stretch of 7 flowers
              bouquets = 7 / 3 = 2

Result:
    Minimum day = 12

Test Case 3 (Edge Case)

Input: bloomDay = [1, 2, 3], m = 2, k = 2
    Need total flowers = m * k = 4
    Available flowers = 3

Action:
    No day can ever create 4 flowers from only 3 positions.

Result:
    Answer = -1

The important pattern is that as the day increases, the set of bloomed flowers only grows. A day that works will never become invalid later. That monotonicity is the exact signal that binary search fits.

A future problem should immediately trigger this approach when you see: “find minimum / maximum value such that a condition becomes true”, and the condition becomes easier as the candidate value increases.

Step 5 — Optimized Solution

This problem has one meaningful optimized solution: binary search on the answer with a greedy feasibility check.

The further insight is simple but powerful: instead of testing every day, test only a logarithmic number of candidate days. For each candidate day, count how many bouquets can be formed from consecutive bloomed flowers.

Algorithm Name: Binary Search on Answer + Greedy Scan

Optimized Pseudocode

function canMake(day):
    bouquets = 0
    streak = 0

    for each bloom in bloomDay:
        if bloom <= day:
            streak += 1
            if streak == k:
                bouquets += 1
                streak = 0
        else:
            streak = 0

    return bouquets >= m

function minDays(bloomDay, m, k):
    if m * k > length(bloomDay):
        return -1

    left = minimum value in bloomDay
    right = maximum value in bloomDay
    answer = -1

    while left <= right:
        mid = left + (right - left) / 2

        if canMake(mid):
            answer = mid
            right = mid - 1
        else:
            left = mid + 1

    return answer

Full Working C++17 Code

int minDays(vector& bloomDay, int m, int k) {
    long long need = 1LL * m * k;
    if (need > (long long)bloomDay.size()) return -1;

    int left = *min_element(bloomDay.begin(), bloomDay.end());
    int right = *max_element(bloomDay.begin(), bloomDay.end());

    auto canMake = [&](int day) -> bool {
        int bouquets = 0;
        int streak = 0;

        for (int bloom : bloomDay) {
            if (bloom <= day) {
                streak++;
                if (streak == k) {
                    bouquets++;
                    streak = 0;
                }
            } else {
                streak = 0;
            }
        }

        return bouquets >= m;
    };

    int ans = -1;
    while (left <= right) {
        int mid = left + (right - left) / 2;

        if (canMake(mid)) {
            ans = mid;
            right = mid - 1;
        } else {
            left = mid + 1;
        }
    }

    return ans;
}

How the Extreme Edge Case Is Handled

Input: bloomDay = [1, 2, 3], m = 2, k = 2

Check first:
    m * k = 4
    n = 3

Since need > available, return -1 immediately.
No binary search is needed.

Time Complexity: O(n log R), where R = max(bloomDay) - min(bloomDay) + 1. Each feasibility check scans the array once in O(n), and binary search needs O(log R) checks.

Space Complexity: O(1). The feasibility check uses only a few counters, and no extra data structure is needed.

Final Intuition to Remember

Whenever the problem asks for the minimum day / smallest value / earliest threshold and the validity of a candidate threshold only gets easier as the threshold increases, think binary search on answer. Then design a greedy check that answers: “Can I make enough valid groups by this threshold?”
