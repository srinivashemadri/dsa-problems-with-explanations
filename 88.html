LeetCode 88 — Merge Sorted Array

Step 1 — Problem Statement

Input: Two sorted integer arrays are given, where the first array nums1 has size m + n. The first m elements of nums1 are valid, and the last n positions are empty space meant to hold the merged result. The second array nums2 has size n.

Output: Merge both sorted arrays into nums1 in non-decreasing order, in-place.

Key Constraints: Both arrays are already sorted. The result must be stored inside nums1. You should not return a new array. The extra space should be constant if possible.

Edge Cases: m = 0 means nums1 starts empty and should become a copy of nums2. n = 0 means nums2 is empty and nums1 should remain unchanged. Duplicate values must be preserved correctly. Negative numbers are valid if present. If one array is fully smaller than the other, the merge should still be correct without special branching.

Step 2 — Problem Understanding & Approach Overview

This problem is really asking you to combine two already-sorted sequences into one sorted sequence without using a separate result array.

The core algorithmic challenge is that nums1 has extra space, so we must avoid overwriting useful values before they are compared.

Category: Two pointers / In-place merge / Array manipulation.

Mental model: Think of two sorted stacks of numbers and place the largest remaining number at the end of nums1 first. That way, you never destroy unread data.

Subtle trap: Many candidates try to merge from the front, which overwrites values in nums1 before they are used. The safe direction is from the back.

Step 3 — Brute Force Solution

The naive way is to create a temporary array, merge both sorted arrays into it with two pointers, and then copy the result back into nums1. 

pseudocode:

create temp array
set i = 0, j = 0

while i < m and j < n:
    if nums1[i] <= nums2[j]:
        append nums1[i] to temp
        i++
    else:
        append nums2[j] to temp
        j++

append remaining elements from nums1
append remaining elements from nums2

copy temp back into nums1

Time Complexity: O(m + n) because each element is processed once during the merge and once during the copy-back step.

Space Complexity: O(m + n) because of the extra temporary array.

Bottleneck: The extra memory usage. The problem specifically invites an in-place solution, so this approach is not optimal for interviews.

Step 4 — Intuition Building

Test Case 1

Input: nums1 = [1, 2, 3, 0, 0, 0], m = 3; nums2 = [2, 5, 6], n = 3

The useful part of nums1 is already sorted. nums2 is also sorted. If we merge from the front, nums1[0] = 1 may get overwritten too early.

Action: Compare from the back, choose the larger value each time, and place it at the last free position of nums1.

Result: [1, 2, 2, 3, 5, 6]

Test Case 2

Input: nums1 = [4, 5, 6, 0, 0, 0], m = 3; nums2 = [1, 2, 3], n = 3

Every element in nums1 is already larger than every element in nums2. If we merged from the front, we would keep shifting nums1 repeatedly. From the back, the answer becomes easy: keep placing nums1 values first.

Action: Fill nums1 from the end with 6, 5, 4, then copy 3, 2, 1.

Result: [1, 2, 3, 4, 5, 6]

Test Case 3 (Edge Case)

Input: nums1 = [0, 0, 0], m = 0; nums2 = [2, 5, 6], n = 3

There are no valid elements in nums1. A front-based merge would still work with extra code, but the backward method handles it naturally.

Action: Since nums1 has no valid values, copy nums2 directly into nums1 from the back.

Result: [2, 5, 6]

The key pattern is clear now: when one array has empty space at the end, and both arrays are sorted, think merge from the back. That signal should immediately trigger the two-pointer backward strategy.

Step 5 — Optimized Solution

There is only one meaningful optimized solution here: the backward two-pointer merge. It is already optimal in both time and space for this problem.

Idea: Use three pointers — one at the end of the valid part of nums1, one at the end of nums2, and one at the last index of nums1. Repeatedly place the larger of the two pointed values into the current back position of nums1. 

pseudocode:

i = m - 1
j = n - 1
k = m + n - 1

while i >= 0 and j >= 0:
    if nums1[i] > nums2[j]:
        nums1[k] = nums1[i]
        i--
    else:
        nums1[k] = nums2[j]
        j--
    k--

while j >= 0:
    nums1[k] = nums2[j]
    j--
    k--

Why this works: The largest remaining element among the two sorted arrays must belong at the end of the final merged array. By filling from the back, we preserve all unread elements in nums1.

Full Working C++17 Code: 

void merge(vector<int>& nums1, int m, vector<int>& nums2, int n) {
    int i = m - 1;
    int j = n - 1;
    int k = m + n - 1;

    while (i >= 0 && j >= 0) {
        if (nums1[i] > nums2[j]) {
            nums1[k] = nums1[i];
            i--;
        } else {
            nums1[k] = nums2[j];
            j--;
        }
        k--;
    }

    while (j >= 0) {
        nums1[k] = nums2[j];
        j--;
        k--;
    }
}

Dry Run on Test Case 1

Input: nums1 = [1, 2, 3, 0, 0, 0], nums2 = [2, 5, 6]

Initial State:

i = 2  -> 3
j = 2  -> 6
k = 5  -> last position

Step 1: Compare nums1[i] = 3 and nums2[j] = 6

Pivot decision: 6 is larger
Place 6 at nums1[5]
Array: [1, 2, 3, 0, 0, 6]

Step 2: Compare nums1[i] = 3 and nums2[j] = 5

Place 5 at nums1[4]
Array: [1, 2, 3, 0, 5, 6]

Step 3: Compare nums1[i] = 3 and nums2[j] = 2

Place 3 at nums1[3]
Array: [1, 2, 3, 3, 5, 6]

Step 4: Compare nums1[i] = 2 and nums2[j] = 2

Place 2 from nums2 at nums1[2]
Array: [1, 2, 2, 3, 5, 6]

Step 5: nums2 is exhausted, stop

Final Result: [1, 2, 2, 3, 5, 6]

Edge Case Handling: If nums2 is empty, the main loop never runs and nums1 stays unchanged. If nums1 has no valid elements, the leftover nums2 values are copied directly into nums1. Duplicates are preserved because the comparison always places one valid element at a time.

Time Complexity: O(m + n). Each pointer moves only left, so each element is touched at most once.

Space Complexity: O(1). The merge happens in-place using only a few integer variables.

Algorithm Name: Backward Two-Pointer Merge.
