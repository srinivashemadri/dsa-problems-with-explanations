LeetCode 84 — Largest Rectangle in Histogram

Step 1 — Problem Statement

Input: An array of non-negative integers where each value represents the height of a bar in a histogram, and every bar has width 1.
Output: The area of the largest rectangle that can be formed using one or more contiguous bars.
Key Constraints: The rectangle must be continuous; you cannot skip bars. The height of the rectangle is limited by the shortest bar inside that span. The width is the number of bars included. Because the answer can come from any span, every bar may act as the limiting height for some rectangle.
Edge Cases: Empty array should return 0. A single bar should return its own height. All bars equal should form one wide rectangle. Strictly increasing or strictly decreasing arrays are important because they expose the need to find nearest smaller bars. Repeated equal heights are also tricky because they affect how the stack is maintained. Large widths can make area large enough that using a wider integer type is safer during intermediate multiplication.

Step 2 — Problem Understanding & Approach Overview

This is really asking: for every bar, how far can that bar extend to the left and right while still remaining the limiting height of the rectangle? The core challenge is to avoid checking every possible subarray and recomputing its minimum again and again. This is a monotonic stack problem, specifically a nearest-smaller-element pattern. The mental model is simple: keep bars in increasing height order, so when a shorter bar appears, you immediately know which taller bars just lost their chance to extend further. The subtle trap is to think only about where a bar sits, instead of thinking about the span over which it remains the minimum height.

Step 3 — Brute Force Solution

The most naive approach is to try every possible subarray, compute the minimum height inside it, and use minHeight * width as the rectangle area. 

for left from 0 to n-1:
    for right from left to n-1:
        minHeight = minimum value in heights[left..right]
        area = minHeight * (right - left + 1)
        update answer

This is expensive because for every pair (left, right), we may scan the whole range again to find the minimum.
Time Complexity: O(n3) in the pure naive form, because there are O(n2) subarrays and each minimum can cost O(n).
Space Complexity: O(1).
The bottleneck is repeated minimum-search work across overlapping intervals.

Step 4 — Intuition Building

Test Case 1

Input: 2
    Only one bar exists, so the rectangle can only use that bar.
Action: Treat the bar as width 1.
Result: 2

This looks trivial, but it confirms an important idea: a bar may become a full rectangle by itself if nothing smaller blocks it. A naive approach would still try many ranges, but the optimal approach should instantly preserve this area when the bar is popped at the end.

Test Case 2

Input: 3 2 1
    Heights are strictly decreasing.
    Each new bar is smaller, so previous taller bars cannot extend further to the right.
Action: The stack keeps getting popped as soon as a shorter bar appears.
Result: Areas are checked for 3, then 4 from height 2 over width 2, then 3 from height 1 over width 3.

This test shows why the stack is powerful. The moment a shorter bar arrives, it finalizes the rectangle for taller bars. You do not need to revisit them later.

Test Case 3

Input: 2 1 5 6 2 3
    The key interesting block is 5 6 2.
    Bars 5 and 6 can stretch until the bar 2 appears, which blocks them on the right.
Action: When 2 arrives, pop 6 first, then 5, and compute both rectangles immediately.
Result: The best rectangle is 5 x 2 = 10.

This is the pattern to remember: a bar's best rectangle is determined by the first smaller bar on the left and the first smaller bar on the right. Once you see that, the problem stops feeling like a brute-force interval problem and starts feeling like a boundary-finding problem. A future problem should trigger the same approach whenever you need the widest span around each element under a monotonic condition, especially in histogram, stock-span, and nearest-smaller-element style questions.

Step 5 — Optimized Solution 1 (Intermediate)

The first meaningful optimization is to compute, for every bar, the index of the previous smaller bar and the next smaller bar. Once those two boundaries are known, the largest rectangle using that bar as the limiting height is immediate. This eliminates repeated scanning of subarrays. 

1. Compute previous smaller element index for every bar using a monotonic increasing stack.
2. Compute next smaller element index for every bar using another monotonic increasing stack.
3. For each bar i:
       width = nextSmaller[i] - previousSmaller[i] - 1
       area  = heights[i] * width
       update answer

Time Complexity: O(n). Each bar is pushed and popped at most once in each pass.
Space Complexity: O(n) for the two boundary arrays and the stack.
What was eliminated: the repeated minimum search over every interval.

Step 5 — Optimized Solution 2 (Best Known / Fully Optimal)

The fully optimal version merges boundary discovery and area calculation into one pass. The stack stores indices of bars in increasing height order. When a shorter bar appears, it means every taller bar on the top of the stack has now found its next smaller bar on the right. That is the exact moment to compute its rectangle area. This is the standard monotonic increasing stack solution.

Why the stack stores indices, not heights: because width depends on positions, not just values.

Why the condition uses >= while popping: equal heights should collapse so that only the most recent index remains. That keeps the stack strictly increasing and prevents duplicate boundaries from being treated as separate blockers.

Why the width is i - left - 1: after popping, left is the index of the previous smaller bar. The current bar at i is the first smaller bar on the right. So the valid rectangle spans from left + 1 to i - 1.

int largestRectangleArea(vector<int>& heights) {
    int n = (int)heights.size();
    stack<int> st;
    long long ans = 0;

    for (int i = 0; i <= n; ++i) {
        int curr = (i == n ? 0 : heights[i]);

        while (!st.empty() && heights[st.top()] >= curr) {
            int h = heights[st.top()];
            st.pop();

            int leftSmaller = st.empty() ? -1 : st.top();
            long long width = i - leftSmaller - 1;
            ans = max(ans, 1LL * h * width);
        }

        if (i < n) {
            st.push(i);
        }
    }

    return (int)ans;
}

Why this handles the strict decreasing edge case correctly: each new shorter bar immediately triggers pops, so no bar waits until the end with an incorrect open span.
Why this handles equal heights correctly: using >= collapses duplicates. For example, in 3 3 3, the later 3 replaces the earlier 3 in the active stack, and the final width becomes 3, giving area 9.
Time Complexity: O(n). Every index is pushed once and popped once.
Space Complexity: O(n) for the stack.
Algorithm Name: Monotonic Increasing Stack.

Final Interview Takeaway

The key realization is that every bar is waiting for the first smaller bar on each side. Once you see “largest rectangle under a histogram,” think “nearest smaller to left and right,” and then think “monotonic stack.” That is the signal to reach for this same approach in future problems.
