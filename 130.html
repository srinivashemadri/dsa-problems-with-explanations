LeetCode 130 — Surrounded Regions
Step 1 — Problem Statement

Input: An m x n board containing only 'X' and 'O'. Output: Modify the board in place so that every region of 'O' completely surrounded by 'X' is flipped to 'X'. Any 'O' connected to the border must remain unchanged.

Key Constraints: The board is rectangular, the operation must be done in place, and connectivity is 4-directional only. A region is captured only if none of its cells can reach any border cell through adjacent 'O' cells.

Edge Cases: empty board, one row, one column, all 'X', all 'O', a single isolated interior 'O', and large border-connected chains that snake through the grid.

Step 2 — Problem Understanding & Approach Overview

This problem is really asking: which 'O' cells are unsafe because they are trapped away from the border? The core challenge is not to find the captured cells directly, but to identify the safe cells first.

This is a graph traversal / flood fill problem on a grid. The instinctive mental model is: every border 'O' acts like an escape point, so any 'O' reachable from the border must survive. The subtle trap is trying to inspect every region independently and repeatedly; that wastes work and often leads to incorrect border handling.

Step 3 — Brute Force Solution

Naively, for every 'O', run DFS/BFS to check whether its component touches the border. If it does, leave it. If it does not, flip that whole component to 'X'. 

For each cell (i, j):
    if board[i][j] == 'O' and not visited:
        run DFS/BFS from (i, j)
        collect all cells in this component
        if any cell in this component touches the border:
            keep them as 'O'
        else:
            flip all collected cells to 'X'

Time Complexity: O((m*n)^2) in the worst case. In a board full of 'O', each component check may traverse nearly the entire grid, and there can be many starting cells.

Space Complexity: O(m*n) for visited state and traversal stack/queue.

The bottleneck is repeated traversal of overlapping regions.

The key insight appears here: it is easier to discover the safe region from the border than to prove every interior region is trapped. The signal that should immediately make you think of this approach is: “cells/components connected to the boundary must be preserved.”

Step 5 — Optimized Solution

There is one fully optimal idea here: perform a multi-source flood fill from every border 'O'. Mark every reachable 'O' as safe. After that, any remaining 'O' is definitely enclosed and can be flipped.

This is often called multi-source BFS flood fill.

Why this works: If an 'O' can be reached from the border through other 'O' cells, then it is not surrounded. So border reachability is exactly the safety criterion.

Why start from the border and not from every interior cell? Because the border gives you the only cells that are guaranteed to survive. From there, you expand only once into the safe area. This removes repeated region checks.

Pseudocode:

1. Push every border 'O' into a queue and mark it as safe, for example with '#'.
2. While the queue is not empty:
       pop one cell
       for each of 4 directions:
           if neighbor is inside the board and is 'O':
               mark it '#'
               push it into the queue
3. After BFS ends:
       flip every remaining 'O' to 'X'
       convert every '#' back to 'O'

Full Working C++17 Code:

void solve(vector<vector<char>>& board) {
    int m = board.size();
    if (m == 0) return;
    int n = board[0].size();
    if (n == 0) return;

    queue<pair<int, int>> q;

    auto pushIfO = [&](int r, int c) {
        if (board[r][c] == 'O') {
            board[r][c] = '#';
            q.push({r, c});
        }
    };

    for (int i = 0; i < m; ++i) {
        pushIfO(i, 0);
        if (n > 1) pushIfO(i, n - 1);
    }

    for (int j = 0; j < n; ++j) {
        pushIfO(0, j);
        if (m > 1) pushIfO(m - 1, j);
    }

    int dr[4] = {1, -1, 0, 0};
    int dc[4] = {0, 0, 1, -1};

    while (!q.empty()) {
        auto [r, c] = q.front();
        q.pop();

        for (int k = 0; k < 4; ++k) {
            int nr = r + dr[k];
            int nc = c + dc[k];

            if (nr >= 0 && nr < m && nc >= 0 && nc < n && board[nr][nc] == 'O') {
                board[nr][nc] = '#';
                q.push({nr, nc});
            }
        }
    }

    for (int i = 0; i < m; ++i) {
        for (int j = 0; j < n; ++j) {
            if (board[i][j] == 'O') board[i][j] = 'X';
            else if (board[i][j] == '#') board[i][j] = 'O';
        }
    }
}

Extreme Edge Case Handling:

Case: 1 x N or M x 1 board

Example:
O X O O X

    Every cell lies on the border
    All O's are automatically safe
    BFS marks them, final flip step changes nothing

This is exactly where a naive “interior region” mindset can fail,
but border flood fill handles it naturally without special-case logic.

Time Complexity: O(m*n). Each cell is visited at most once during BFS, and each cell is processed a constant number of times in the final pass.

Space Complexity: O(m*n) in the worst case for the queue. The board itself is modified in place, so no extra visited matrix is needed.

Final Interview Intuition

The pattern to remember is: when a grid problem asks you to preserve cells connected to the edge, do not search from the middle. Start from the border, mark all reachable “safe” cells, then flip the rest. That single shift in perspective turns a repetitive region-checking problem into a clean linear-time flood fill.
