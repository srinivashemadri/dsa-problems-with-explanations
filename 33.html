LeetCode 33 — Search in Rotated Sorted Array
1. Problem Statement

Input: An integer array nums that was originally sorted in strictly increasing order, then rotated at an unknown pivot, and an integer target. Your task is to determine the index of target in nums.

Output: Return the index of target if it exists; otherwise return -1.

Key Constraints: The array has no duplicates in the standard version of this problem, which is the detail that makes the binary-search logic clean. The array is rotated, but both halves around the pivot remain individually sorted.

Edge Cases: empty array, single element, target absent, target at the pivot, no rotation at all, full rotation equivalent to no rotation, and arrays where the target lies in the left sorted half or the right sorted half.

2. Problem Understanding & Approach Overview

This problem is really asking: how do we do binary search when the array is not fully sorted globally, but is still partially sorted because of rotation?

The core challenge is identifying, at every step, which half is sorted and then deciding whether the target can only live inside that half.

Category: Modified binary search.

Mental model: Picture the rotated array as two sorted blocks stitched together. One of the two halves around the midpoint is always sorted. Once you know which half is sorted, you can check whether the target belongs there and discard the other half.

Common trap: Many candidates try to “find the pivot first” and then do a second binary search. That works, but the cleaner interview solution is a single-pass modified binary search that directly narrows the range.

3. Brute Force Solution

The naive approach is to scan the array linearly and compare every element with the target. 

for i from 0 to n - 1:
    if nums[i] == target:
        return i
return -1

Time Complexity: O(n). We may inspect every element once.

Space Complexity: O(1). No extra data structure is needed.

Bottleneck: The search does not exploit the sorted structure, so it wastes the main advantage the problem gives us.

4. Intuition Building
Test Case 1

Input: nums = 4 5 6 7 0 1 2, target = 0
    Mid starts near 7
    Left half 4 5 6 7 is sorted
    Target 0 is not in [4, 7]
Action: Discard left half and search right half.
Result: Eventually land on index 4.

Test Case 2

Input: nums = 4 5 6 7 0 1 2, target = 6
    Mid may be 7 initially
    Left half 4 5 6 7 is sorted
    Target 6 lies inside [4, 7]
Action: Discard right half and keep searching left half.
Result: Eventually land on index 2.

Test Case 3 (Edge Case)

Input: nums = 1, target = 1
    Single element, both bounds and mid are the same
Action: Direct comparison succeeds immediately.
Result: Return 0.

The important discovery is this: even though the whole array is not sorted, one side around mid is always sorted. That is enough to make binary search work. The signal that should immediately make you think of this approach is: “sorted array, but rotated once, with unique values.”

5. Optimized Solution

There is one optimal solution here: a single modified binary search. At each step, detect the sorted half, then decide whether the target belongs there. 

int search(vector<int>& nums, int target) {
    int left = 0, right = (int)nums.size() - 1;

    while (left <= right) {
        int mid = left + (right - left) / 2;

        if (nums[mid] == target) return mid;

        // Left half is sorted
        if (nums[left] <= nums[mid]) {
            if (nums[left] <= target && target < nums[mid]) {
                right = mid - 1;
            } else {
                left = mid + 1;
            }
        }
        // Right half is sorted
        else {
            if (nums[mid] < target && target <= nums[right]) {
                left = mid + 1;
            } else {
                right = mid - 1;
            }
        }
    }

    return -1;
}

Dry Run:

Input: nums = 4 5 6 7 0 1 2, target = 0
Step 1: left = 0, right = 6, mid = 3, nums[mid] = 7
    Left half 4 5 6 7 is sorted
    Target 0 is not in [4, 7)
Action: left = mid + 1 = 4
Step 2: left = 4, right = 6, mid = 5, nums[mid] = 1
    Left half 0 1 is sorted
    Target 0 is in [0, 1)
Action: right = mid - 1 = 4
Step 3: left = 4, right = 4, mid = 4, nums[mid] = 0
Final Result: return 4

Extreme Edge Case Handling: If the array is not rotated at all, the left half is always sorted and the logic behaves exactly like normal binary search. If the target is absent, the search space keeps shrinking until left > right, and then we return -1.

Time Complexity: O(log n). Each iteration discards half of the remaining search space.

Space Complexity: O(1). The algorithm uses only a few pointers.

Algorithm Name: Modified Binary Search.
