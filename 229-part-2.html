Why initialize cand1 = 0, cand2 = 1? — Deep Explanation
Core Answer (Short & Honest)

There is no real algorithmic logic behind choosing cand1 = 0 and cand2 = 1. These are just dummy initial values to make the variables valid before the loop starts.

The algorithm does NOT depend on these initial values at all. What actually matters is the counts, not the candidate values initially.

Why It Still Works (Important Insight)

Look at the decision flow carefully: 

if (x == cand1)        → use cand1
else if (x == cand2)   → use cand2
else if (count1 == 0)  → replace cand1
else if (count2 == 0)  → replace cand2
else                   → decrement both

Notice something critical:

When count1 == 0 or count2 == 0, we overwrite the candidate.

That means:

  • Initial values are temporary placeholders
  • They get replaced as soon as real data arrives
  • So correctness does NOT depend on them
Step-by-Step Reality Check

Test Case

Input: 5 5 5 2 2 2

Initial state: 

cand1 = 0, count1 = 0
cand2 = 1, count2 = 0

Now process:

x = 5
→ count1 == 0 → cand1 = 5, count1 = 1

Immediately, the fake value 0 is gone.

From here onward, algorithm behaves correctly.

What If nums Contains 0 or 1?

Even if input contains 0 or 1:

  • If count is 0 → candidate gets replaced anyway
  • If count > 0 → comparison works normally

So there is no collision issue.

The Real Principle (This Is What Matters)

The algorithm relies on:

  • Counts becoming zero
  • Candidates being replaced dynamically
  • Final verification pass

Not on initial candidate values.

Better / Cleaner Initialization (Recommended in Interviews)

To avoid confusion, many engineers prefer writing it like this: 

int cand1 = 0, cand2 = 0;
int count1 = 0, count2 = 0;

Or even conceptually:

"Candidates are undefined until counts become non-zero."

Subtle Trap Most Candidates Miss

People think:

"Initial candidate values must be meaningful."

That is wrong.

What actually matters:

The moment count becomes 0 → candidate loses identity → can be replaced.

Final Takeaway

cand1 = 0 and cand2 = 1 are just placeholders.

The algorithm works because:

  • Counts control validity
  • Candidates are replaceable
  • Final pass guarantees correctness

If you understand this, you understand Boyer-Moore at a deep level.
